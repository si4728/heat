# 동시사용 및 엑셀 내보내기 개선 — 2026-10-04

## 적용 사항

- DB 스키마 3.14.0 유지. SQLite 실행 엔진은 3.45.3에서 3.53.4로 업그레이드.
- SQLite 공식 Windows x64 DLL을 프로젝트 `runtime/sqlite`에 설치. 다운로드 ZIP의 SHA3-256을 공식 다운로드 페이지 값과 대조함. 운영 `.venv`의 `sitecustomize.py`에서 해당 DLL을 먼저 로드함. 시스템 Python 설치 파일은 변경하지 않음.
- `server.py`는 SQLite 3.51.3 미만이면 시작을 거부함. `/api/health`에 실제 `sqlite_version` 표시.
- 요청마다 별도 ORM Session을 사용하고 Engine 설정 및 SQL 컴파일 캐시를 재사용. NullPool로 각 세션 종료 시 실제 연결을 닫아 복구 및 임시 DB 정리와 호환성을 유지.
- 전체 엑셀 5개 데이터 조회를 명시적 `BEGIN`으로 묶어 동일 시점의 읽기 스냅샷 확보. 엑셀 서식 및 압축 전에 DB 읽기 트랜잭션 종료.
- 전체 엑셀은 단일 생성 잠금으로 중복 생성을 방지. 생성 완료한 불변 바이트를 재사용하고 각 요청에 독립 BytesIO를 전달.
- 영구 읽기 전용 연결의 `PRAGMA data_version`으로 다른 연결의 커밋 감지. DB 파일 식별 정보 변경 시에도 무효화. 생성 중 커밋이 발생한 결과는 캐시에 보관하지 않음. 생성 실패 시 과거 자료를 대신 반환하지 않음.
- 캐시는 프로세스 내부에서 최대 4개 DB로 제한. 서버 재시작 시 소멸. 다중 프로세스 간 공유 캐시는 아님. 현재 배포는 단일 Waitress 서버, 8개 작업 스레드.
- 셀마다 생성하던 동일 Alignment/Fill 객체를 재사용하여 엑셀 서식 처리 비용 감소.
- 첫 생성 작업은 별도 Python 프로세스에서 수행. 서버는 생성 완료를 기다리되 동일 자료에 대한 생성은 1개로 제한. 임시 출력은 작업별 임시 디렉터리에 저장 후 읽어 삭제하며 요청 간 경로를 공유하지 않음. 최대 실행시간은 300초. 작업 실패 시 과거 자료를 반환하지 않음.

## 설치 복구 방법과 범위

- 재배포: DLL과 manifest 및 sitecustomize 템플릿을 함께 보관하고 `runtime/sqlite/install_runtime.ps1` 실행. `.venv`의 Python으로 서버 시작.
- 원래 Python의 SQLite DLL은 그대로 보존되어 있으나, 운영 서버는 수정된 WAL 엔진이 필요하므로 구형 엔진으로의 재시작은 차단됨.
- 동일 레코드의 오래된 화면 저장 충돌 방지와 대량 입력/ML 작업의 별도 작업 큐는 이번 엑셀·실행 엔진 개선 범위에 포함하지 않음.

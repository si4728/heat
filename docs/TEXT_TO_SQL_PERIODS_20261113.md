# Text-to-SQL 공통 기간 처리

검사 횟수 순위와 일반 검사 요약·상위 Tube·감육률 조건 조회에 공통 기간 해석기를 적용했다. 날짜를 모델 생성 SQL에 맡기지 않고 서버가 허용 설비와 검사 회차를 확정한다. 기존 SQL 문법 및 읽기 전용 계정 제한은 유지한다.

지원 예시:

- `최근 3개월 검사 결과를 요약해 줘.`
- `최근 30일 감육률 30% 이상인 Tube를 보여줘.`
- `2025년 감육이 가장 심한 Tube 5개를 알려줘.`
- `2025년 3월 검사 결과를 요약해 줘.`
- `2025-01-01~2025-12-31 검사를 제일 많이한 튜브 10개 리스트 해줘, 튜브번호 별 1행씩`
- `2025-01-01부터 2025-12-31까지 검사 결과를 요약해 줘.`
- `올해`, `작년`, `전체 이력`도 같은 방식으로 지정한다.

기준일은 한국 시간이다. 양 끝 날짜를 포함하고, 미래 기록은 제외한다. 최근 N년·N개월은 달력 기준으로 이전 날짜를 계산하며 말일은 해당 월의 마지막 날로 보정한다. 최근 N일의 시작일은 오늘에서 N일 전이다. 검사일이 없으면 보고일을 사용한다. 잘못된 날짜, 시작일 역전, 복수 기간, 지원하지 않는 기간 표현은 모델 호출 전에 거절한다.

기간이 있는 일반 조회는 기간 내 모든 유효 검사 회차를 대상으로 한다. 같은 튜브가 여러 회차에 있으면 별도 검사 결과로 집계한다. 따라서 요약 건수는 고유 튜브 수가 아닌 검사 결과 수이다. 단일 설비에서 검사 회차를 지정하면 기간 조건도 함께 만족해야 한다. 기간 내 검사 없음·날짜 없음 설비는 제외 목록에 표시하며, 전체가 비면 안내 오류를 반환한다. 회차가 500개를 넘으면 기간 또는 설비 범위를 좁히도록 안내한다.

기간이 없으면 일반 조회는 최신 또는 지정 회차, 설비 검사 횟수 순위는 최근 5년, 튜브 순위는 전체 이력이라는 기존 기본값을 유지한다. 순위의 개수와 기간의 숫자는 분리해서 해석한다. 횟수 순위는 지정 회차와 무관하게 이력을 집계한다.

일반 조회에서는 기간과 검사 ID 목록을 생성 토큰에 서명하고, 실행 시 설비 권한·회차 유효성·기간 내 날짜를 다시 검사한다. 실행 요청의 기간이나 설비 값으로 서명한 범위를 바꿀 수 없다. CLI의 자연어 조회에도 같은 기간 처리를 적용한다. 수명 예측, 차기검사, 기간 간 비교는 여전히 지원하지 않는다.

검증: 관련 Python 테스트 143건 통과. 실제 MariaDB에서 기간 내 여러 회차 요약을 독립 집계와 비교했으며, 기간 밖 회차 실행 차단도 확인했다. 로컬 Node 실행 파일이 없어 JavaScript 문법 검사 및 브라우저 검증은 수행하지 못했다. 서버 재시작 및 다른 PC 배포는 별도이다.

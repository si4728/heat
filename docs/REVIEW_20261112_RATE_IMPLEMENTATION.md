# 2026-11-12 고객 추가 회신 반영

대상: VCM1·VCM2. 근거: 고객의 적용 감육속도 b·c안 병행, 현재 승인 설계 수량 a안, 허용 Plugging 비율 b안 회신. [확정 사항 D07~D09](REVIEW_20261112_DECISIONS.md).

## 적용 동작

| 조건 | 적용 감육속도 | 산정 근거 표시 |
|---|---|---|
| 현재 설치 이후 유효 측정일 3회 이상, 회귀값 양수 | 두께-검사일 선형 회귀의 감육속도 | 추세(n회) |
| 3회 이상, 회귀값 0 이하 | 양의 장기값 | 추세 0 이하 → 장기 |
| 3회 이상, 회귀 연산 불가 | 양의 장기값 | 추세 산정 불가 → 장기 |
| 2회 이하, 단기값이 양수이며 장기보다 큼 | 단기값 | 단기 |
| 2회 이하, 장기값이 더 크거나 단기 산정 불가 | 양의 장기값 | 장기 |
| 2회 이하, 단기값 0 이하 | 양의 장기값 | 단기 0 이하 → 장기 |
| 적용 가능한 양의 값 없음 | 예측 없음 | 산정 불가 |

회귀는 실제 측정 두께(mm)를 날짜 차이/365.2425(년)에 대해 최소제곱 회귀하고 기울기에 -1을 곱한다. 가정상 설치 공칭두께는 회귀 표본에 넣지 않는다. 같은 날짜의 이전 중복 결과는 최소 유효 두께 한 건으로 취급하고 최신 측정은 서비스에서 선택한 실제 결과를 사용한다. 무효·대체 검사와 현재 설치 이전 측정은 제외한다.

3회 이상의 양의 회귀값은 최근 두 측정의 단기값이 음수여도 사용한다. 이 경우 최근 한 회차의 편차를 평균하는 회귀 우선 규칙을 따른다. 회귀값이 0 이하인 경우에는 단기값이 양수여도 장기로 전환한다.

선정값과 원래 단기·장기·회귀값을 별도로 반환한다. 화면의 선택 튜브 표·전체 측정표·상세 화면에 같은 산정 근거를 표시한다. 배율은 선정값에만 곱하고, 장기값이나 근거 문구를 바꾸지 않는다. 예측 시작일은 기존의 현재 계산 기준일을 유지했다. 검사 표본 기반 전체 최대 감육률 추정 모델은 기존 그림 5의 별도 계산으로 유지한다.

전체 튜브 수는 현재 승인 사양의 `tube_count`만 사용한다. 승인 사양이 없으면 보고서·Bundle 예상 수량·등록 Tube 수로 대체하지 않는다. 해당 설비의 허용 수량과 잔여수명은 산정 불가이며 개별 유효 튜브의 예측은 유지한다. 그래프에 승인 수량 미등록을 허용 한도 0개로 그리지 않는다.

## 비율 설정

`hx_configuration.conf`의 `[remaining_life]`:

```ini
default_allowable_plugging_percent = 20
normal_allowable_plugging_percent = 20
critical_allowable_plugging_percent = 20
```

일반·Critical 모두 기본 20%로 계산하며 기존 DB에 과거 자동 저장된 Critical 10%를 재사용하지 않는다. 향후 중요도별 기준 변경은 마지막 두 설정을 1~20의 정수로 변경하고 애플리케이션을 재시작하면 된다. 계산·관리 입력 화면·저장에 같은 설정을 사용한다. 기존 Simulation의 명시적 비율은 유지한다. 별도의 설비별 한도 편집 기능이나 새 DB 컬럼은 추가하지 않았다.

허용 수량 = 현재 승인 설계 수량 × 설정 비율 / 100을 내림한 정수. 기존의 ‘허용 수량 최초 초과’ 판정은 유지한다. 감육률 기준 40%를 허용 수량 비율 20%로 바꾸는 변경이 아니다.

## 검증

- IRIS2 `.venv/Scripts/python.exe`로 관련 Python 시험 110건 통과. 회귀 우선·단기/장기 선택·0 이하 전환·동일 날짜·설치 경계·중복·결측·오버플로·배율·승인 사양 부재·중요도별 설정을 포함한다.
- JavaScript 시험 파일 12개 통과. 기본 일반·Critical 20%, 추후 중요도별 설정값, 승인 수량 부재와 실제 Plugging 날짜 보존을 포함한다.
- 실제 개발 MariaDB의 VCM1·VCM2 212대, 배율 0.1/0.5/1/1.5/2의 1,060개 사례를 대조했다. 서버·브라우저 예측일 비교 7,331건 불일치 0건.
- 인증된 분석 화면에서 1440/768/390px로 Map↔표↔그래프 연동, 선정 근거, 2배 배율의 적용값과 장기 원값 보존을 확인했다. 페이지 가로 넘침 없음. 원래 색상·글꼴·배치를 유지했다.
- E-104B의 기존 표본 추정은 실측 최대 23.22%, 전체 추정 최대 31.7469%, 상위 20% 경계 21.6982%, 도달 연도 2026/2032로 유지됨을 확인했다.
- 전체 Python 시험 269건 중 264건 통과, 기존 화면 검증 5건은 미해결이다: `test_data_entry_status_access`의 옛 sidebar 설정 메뉴 탐색 3건 오류와 옛 PDF 설명 문구 검사 1건 실패, `test_text_to_sql_mariadb`의 옛 일반 메뉴 Text-to-SQL 링크 검사 1건 실패. 관련 새 계산 시험은 통과하며 전체 검증을 통과로 표시하지 않는다.
- 로컬 근거: `reports/review-decisions-20261112/`, `reports/exchanger-analysis-20261112/`, `reports/system_recheck/20261028/life_consistency.json`, `life_browser_parity.json`, `reports/sample-wall-loss-20261112/`.

소스와 결정 문서를 수정했다. 기존 업무 DB의 설계 수량·중요도·비율을 일괄 갱신하지 않았고 운영 서버를 재시작하거나 배포하지 않았다. 기존 실행 프로세스에 반영하려면 재시작이 필요하다. Git 커밋·원격 업로드는 이번 변경에서 수행하지 않았다.

## 실제 로컬 서버 화면 재확인

사용자의 실제 화면 재확인 요청에 따라 4824 포트 상태를 조회했다. 실행 중인 웹 서버가 없어 IRIS2 전용 `.venv/Scripts/python.exe server.py --host 127.0.0.1 --port 4824 --no-browser`로 새 서버를 시작했다. MariaDB 상태는 정상이다. 이 확인은 저장된 HTML 미리보기가 아닌 실제 `http://127.0.0.1:4824` HTTP 화면에서 수행했다.

- 실제 인증·권한 검사를 유지하고 비로그인 접근이 로그인으로 이동함을 확인했다.
- E-111(100), Tube 14-4: `추세(4회)`, 적용 속도 0.1440 mm/년. Tube 7-16: `추세 0 이하 → 장기`, 적용 속도 0.0087 mm/년. 현재 DB의 유효 측정값을 사용했으며 문서의 설명용 그림 수치로 보정하지 않았다.
- 1440/768/390px에서 Map·표 선택에 그래프·선택 표가 함께 갱신됐다. 2배 슬라이더의 적용 속도와 전체 측정표 값이 일치하고 장기 원값은 유지됐다. 페이지 가로 넘침과 브라우저 실행 오류는 없었다.
- E-111 승인 설계 수량 353본, 한도 20%·70본. 관리 입력 화면에서 일반과 Critical을 각각 선택해도 20%가 유지됐으며 저장은 하지 않았다.

- 실제 HTTP 화면 검사 7개 항목 통과. 근거 및 화면 캡처: `reports/review-live-20261112/validation.json`, `e111-live-1440.png`, `e111-live-768.png`, `e111-live-390.png`, `e111-fallback-live.png`, `e104b-live.png`, `limits-live.png`, `dashboard-live.png`.

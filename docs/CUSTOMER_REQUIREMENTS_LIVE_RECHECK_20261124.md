# 고객 요구사항별 구현 상태와 실제 화면 검증 결과

이 문서는 변경 전 검증 기록이다. 이후 미반영 항목의 구현·로컬 DB 적용·재검증 결과는 [고객 미반영 항목 적용 결과](CUSTOMER_IMPLEMENTATION_20261124.md)를 확인한다.

2026-11-24 · 검증 소스 `85d374e` (기능 구현 `70343e7` 포함) · 검토 범위 PE·VCM1·VCM2

## 결론

**Text-to-SQL의 VCM1·VCM2 설비별 조회와 AI 종합 의견은 실제 서버에서 동작했다. 고객 요구 전체가 완료된 상태는 아니다.** 잔여수명 구간 재분류, 원본 보정, PE 통계 추정/조회 확장, 분석 화면 Plugging 완료·취소, 비동기 모델 대기열은 남아 있다.

추가로 **E-222는 실제 검사 기록이 있음에도 분석 화면에서 NO_INSPECTION으로 분류되는 문제**를 확인했다. 현재 유효 측정 선정과 단일 최신 검사 회차 집계의 차이도 명확히 안내할 필요가 있다.

## 검증 방법과 서비스 상태

- 중지돼 있던 iris2 웹 서버를 검증 동안만 `127.0.0.1:4824`로 가동했다. 실제 Chrome에서 실제 HTTP 페이지·API·MariaDB·Gemma 추론을 사용했다. API 응답을 모의 데이터로 교체하지 않았다.
- 기존 활성 관리자 계정에 대한 메모리 내 인증 세션을 사용했다. 세션 쿠키는 stdin으로만 전달했다. 실제 비밀번호 입력을 통한 로그인 시험은 수행하지 않았다. 익명 접근의 로그인 화면 이동은 실제 HTTP로 확인했다.
- 실제 화면/기능 관찰 28개는 확인 통과 11개, 요구 대비 미반영/불일치 16개, 날짜 표시 관찰 1개로 기록했다. 미반영을 정상 동작으로 간주한 ‘전체 합격’ 보고가 아니다.
- Python 회귀시험은 Text-to-SQL 관련 196건과 감육속도·대시보드·UI 관련 51건, 총 **247건 통과**했다. 기존 동작/거절 정책 시험의 통과는 미구현 고객 기능의 완성을 뜻하지 않는다.
- 업무 데이터 보정·Plugging 등록/취소는 실행하지 않았다. 전후 기존 테이블 63개의 데이터 해시가 일치했다. 정상 HTTP 접근에 따른 `access_audit_event`와 DB revision 카운터는 비교에서 제외했다.
- 검증 종료 후 임시 웹 서버를 중지하고 **4824 포트에 listener가 없음을 확인**했다. MariaDB는 중지하지 않았다.

원본 로그·화면 캡처·검증 JSON은 `reports/live-customer-check-20261124/`에 로컬 보관하며 Git에 포함하지 않는다. 초기 검증 도구가 비어 있는 E-222 분석 데이터를 읽으며 중단된 적이 있어, 도구의 NULL 처리를 고친 뒤 전체 검증을 다시 수행해 정상 종료했다. 제품 코드를 수정해 검증 결과를 바꾸지는 않았다.

### 추가 발견: E-222의 잘못된 무이력 분류

실제 `/analysis?exchanger_id=235`는 E-222 선택 ID를 유지하지만 `selection_status=NO_INSPECTION`으로 Summary/Map을 구성하지 않는다. 다른 설비로 자동 전환되지는 않는다.

DB에는 E-222 검사 4회와 결과 40건이 있다. 품질 상태는 VALID 30건, `USER_APPROVED_211MM_BASIS` 10건이다. `exchanger_wall_loss_ranking()`은 `quality_status='VALID'`만 허용하는 반면, 공통 `measurement_eligibility`는 해당 사용자 승인 상태를 허용한다. 현재 설치기간 필터와 함께 이 차이가 분석 진입 여부에 영향을 준다.

**우선 개선:** 승인 품질 상태를 공통 적격성 함수와 일치시키고, 무이력과 ‘유효 분석 입력 없음’을 별도 상태로 표시한다. 임의 품질 상태 전체를 허용하거나 실제 측정 이력을 새로 만들며 해결하지 않는다. E-105 등 같은 승인 상태를 사용하는 설비의 영향도 함께 확인해야 한다.

### 튜브 수 집계 기준의 확인 결과

E-106의 30% 이상 결과는 최신 2025-11-05 검사 회차에서 35본이다. 현재 분석 화면은 튜브별 최신 유효 측정을 사용하며, 2023-11-11 측정만 남아 있는 1본이 더 포함되어 36본이 된다. 제공된 그림의 31본은 현재 DB의 두 집계 어느 쪽과도 같지 않다.

따라서 **‘최신 검사 회차의 결과’**를 원하는지 **‘분석 화면의 현재 유효 측정’**을 원하는지 기준을 표시/선택하도록 보완하는 것이 좋다. 임의로 31본에 맞추지 않는다. 같은 이유로 최근 검사일 한 칸만 보면서 모든 튜브 수가 그 날짜의 회차 결과라고 해석하면 안 된다.

## 4. 기존 연계 기능 확인

- 검사 PDF는 실제 `/inspections/343/pdf`에 Range 요청을 보내 HTTP 206, application/pdf, `%PDF-` 서명을 확인했다. 모든 검사 회차와 PDF 뷰어의 페이지 이동 전체를 검증한 것은 아니다.
- 로그온·화면 접근 이력 관리 화면을 실제로 열었고, CSV 응답 200과 `X-Audit-Recorded: 1`을 확인했다. 조회에 따른 정상 감사 행이 누적됐다.
- 서버 health는 IRIS2/MariaDB/status ok, 무결성 ok, 외래키 이슈 0을 반환했다.

## 5. 권장 후속 순서

1. **E-222 등 승인 품질 상태의 분석 진입과 잘못된 무이력 문구를 먼저 수정한다.** 이 상태에서는 Text-to-SQL과 분석 화면의 일치를 전체 설비에 보증할 수 없다.
2. IRIS 미실시/산정 불가 분류와 사유, PE의 날짜·측정 최대값 표시, E-331A 보조 연도를 정리한다.
3. 원본 근거에 따라 E-341 두께와 E-222 현재 수량/보고서 수량을 보정하고 E-122A NDD 처리 정책을 확정한다.
4. PE 추정 계산과 Text-to-SQL 허용 범위를 함께 확장한다. 검사일을 불필요하게 재입력하지 않는다.
5. 완료·취소 원장과 권한·날짜·동시성 검증을 갖춘 분석 화면 Plugging 기능을 구현한다.
6. 튜브 집계 회차 기준을 명확히 하고, 미지원 질문 2~8·계산 스냅샷·모델 비동기 대기열을 단계적으로 추가한다.

본 작업은 검증 및 결과 문서화다. 제품 기능·원본 측정·사양 수량·검사일·Plugging 상태는 변경하지 않았다. main 병합이나 상시 서비스 재가동도 수행하지 않았다.

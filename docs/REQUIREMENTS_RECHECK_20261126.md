## 발견 사항과 재현 근거

### R1. 상태 질문의 조건이 사라져 전체 설비가 반환됨 — 우선 수정

현재 API와 실제 브라우저에서 모두 재현했다.

| 질문 | 기대 대상 | 실제 결과 |
| --- | ---: | --- |
| IRIS 미실시 열교환기를 보여줘 | 285대 | 조건 일치 403대, 100대 표시 |
| 산정 불가 열교환기를 보여줘 | 29대 | 조건 일치 403대, 100대 표시 |

`application/text_to_sql_equipment.py:12`의 조건 해석 결과가 두 질문 모두 `conditions=[]`다. 오류로 거절하지도 않고 일반 목록 조회로 처리한다. 반환 목록에는 CALCULATED·LIMIT_NOT_REACHED·NO_INSPECTION이 섞인다.

**보완:** 지원 상태 필터를 명시적으로 구현하고, 해석하지 못한 조건은 전체 목록으로 처리하지 않도록 한다. 분류 기준을 대시보드와 공유하고 일치 대수를 회귀 검증한다.

### R2. 이미 확인한 한도 초과를 통계 추정이 양의 수명으로 덮어씀 — 우선 수정

운영 DB 보정 없이 순수 계산 함수에 유효한 경계 입력을 넣어 재현했다.

- 설계 수량 100본, 허용 수량 20본.
- 검사 표본 100본 중 79본 감육률 0%, 21본 감육률 40%.
- 이미 실측 기준 도달 21본이므로 실측 수량 예측의 잔여수명은 0년.
- 같은 표본의 Gumbel 추정 20% 경계 감육률은 약 17.999%이며, 공통 Summary는 이를 우선하여 **16.4년**을 표시했다.

`application/equipment_summary.py:26`은 추정값을 우선하고 `:28`의 보호는 **실제 완료 수량** 초과만 검사한다. 이미 알고 있는 **실측 기준 도달 수량/실측 한도 초과**를 보호하지 않는다.

현재 운영 데이터의 검사 이력 설비들을 추가 확인한 결과, ‘실측 결과는 0년인데 Summary가 양수’인 실제 설비는 발견하지 못했다. 이 결과와 별개로 구현의 경계 오류는 재현되므로 새 데이터·정비 사용 전에 보완해야 한다.

**보완:** 실제 완료와 확인된 실측 한도 초과를 공통 대표값의 우선 제약으로 처리하고, 알려진 측정 사실을 통계 추정으로 되돌리지 않도록 한다. 전체 수량을 검사한 경우의 통계 적용 정책도 명확히 한다.

### R3. IRIS 이력이 없지만 실제 완료 수량이 한도를 넘으면 ‘IRIS 미실시’에서 빠짐

직접 계산 입력 `registered_inspection_count=0`, 전체 100본, 실제 완료 21본, 허용 20본에서 `band='short'`가 반환됐다. 요구한 이력 분류라면 IRIS 미실시를 유지하면서 완료 한도 초과 사실을 별도로 보여야 한다.

`application/equipment_summary.py:41`의 산정 가능 분기는 `life_band()`에 검사 이력 수를 전달하지 않는다. IRIS 미실시 판정은 미산정 분기에만 있다. 현재 운영 DB의 새 Plugging 원장은 0건이며 현재 285대 집계에서 이 경계 오류가 발생했다고 확인한 것은 아니다.

**보완:** 검사 이력 분류를 우선 판정하고 정비/위험 상태와 분리해 동시에 표시한다.

### R4. 생산팀 숫자를 눌러도 해당 생산팀으로 좁혀지지 않음

실제 브라우저에서 **PE 생산팀 / 5년 이하 5대**를 선택하자 **전체 생산팀 14대**가 표시됐다. 목록에 PE와 VCM이 함께 있었다.

`templates/dashboard.html:35`의 그룹 링크는 `life_band`만 전달하고 생산팀·공정은 전달하지 않는다. 링크는 `/?life_band=short#remaining-life-list`였다. 행의 합계 링크도 같은 문제가 있다.

**보완:** 팀 또는 공정 필터를 링크·서버 목록 필터에 함께 적용하고, 클릭한 숫자와 펼쳐진 목록의 대수가 같은지 확인한다.

### R5. 분석 선택 목록이 분석에서 제외한 부분 검사를 최대 감육률에 사용함

E-111의 선택 목록/순위는 **50.29%**, 현재 분석 유효 튜브의 최대는 **27.44%**다. 순위의 원천은 검사 87, **2021년 TOPSOUTH**다. 이 회차는 공통 적격성 규칙에서 일부 구간 검사로 제외하는 대상이다.

`services.py:1217`의 순위 SQL은 이력 최대 감육률을 정렬하지만 `domain/measurement_eligibility.py`의 부분 검사 제외 규칙을 공유하지 않는다. 단순 반올림 차이가 아니다.

**보완:** 순위와 분석의 적격성 기준을 맞춘다. 과거 최대/현재 유효 최대를 둘 다 제공한다면 기준·검사일을 구분해 표시하고 제외 대상은 일관되게 처리한다. 원본 측정은 삭제하지 않는다.

## 검증 범위·데이터·서비스 상태

- 기존 관련 자동 시험 **254건 통과**. 새로 발견한 R1~R5를 모두 검증하는 시험은 기존 집합에 없었다. 통과 수를 고객 요구 전체 합격으로 해석하지 않는다.
- 실제 DB는 SELECT 전용 계정으로 보정값·403대 집계를 재확인했다. 65대/10대/14대/29대/285대의 합이 403대다. 조회 전후 업무 revision 값도 일치했다.
- 실제 브라우저에서 복제 MariaDB 전용 임시 서버에 연결했다. 완료/취소 쓰기는 복제 DB에서만 수행했다. 기본 Map 흐름과 1440/768/390px 화면을 확인하고 R1·R4를 실제로 재현해 캡처했다.
- 브라우저 기본 흐름 시험의 AI 응답은 시험용 대체다. 별도 시험에서는 **대체 없이 실제 Gemma**로 첫 사용자의 PE SQL 생성·실행과 두 번째 사용자의 3부분 종합 의견 생성을 확인했다. `running/queued → succeeded/running → succeeded/succeeded` 순서였다.
- 실제 모델 대기 중 추가 시험 작업을 넣어 1건 처리+3건 대기를 만들고 다음 요청의 429를 확인했다. 실제 모델을 4개 동시에 실행한 시험이 아니다. 다른 사용자의 job 조회는 404였다.

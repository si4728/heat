# Text-to-SQL 월별 사용 이력

웹 Text-to-SQL의 SQL 생성·실행 요청을 월별 텍스트 파일에 누적한다. 데이터베이스 테이블이나 조회 SQL의 읽기 전용 권한을 변경하지 않는다.

## 저장 위치와 형식

```text
iris2/logs/text_to_sql/text_to_sql_2026-11.txt
iris2/logs/text_to_sql/text_to_sql_2026-12.txt
```

- 한국시간(UTC+09:00) 기준으로 저장 월을 결정한다.
- UTF-8 JSON Lines 형식: 한 줄에 하나의 완전한 JSON 객체를 기록한다. 파일 전체를 JSON 배열로 다시 쓰지 않고 끝에 한 줄씩 append한다.
- SQL 생성 성공과 실행 성공은 각각 한 세트로 기록하며 같은 `usage_id`로 연결한다. 따라서 SQL을 생성하고 실행하지 않은 경우에도 생성 이력은 남는다. 같은 SQL을 여러 번 실행하면 실행 시도마다 별도의 `event_id`가 추가된다.
- 한 기록 안에 질문·요청한 선택 범위·실제 해석한 설비/검사 회차·SQL·오류를 함께 저장한다. 질문과 SQL 안의 줄바꿈은 JSON 문자열 내부에서 이스케이프하므로 기록 간 구분이 깨지지 않는다.
- 자동 삭제·덮어쓰기 없이 월별로 누적하며 `logs/`는 기존 Git 제외 대상이다. 웹 공개/다운로드 경로는 추가하지 않는다.

## 기록 항목

| 필드 | 내용 |
|---|---|
| `schema_version` | 기록 형식 버전 |
| `usage_id` / `event_id` | 질문 흐름 연결 ID / 개별 생성·실행 시도 ID |
| `event` | `generate` 또는 `execute` |
| `requested_at` / `logged_at` | 요청 기록 시작 / 파일 저장 시각(한국시간) |
| `actor` | 사용자 ID·사용자명·관리자 여부. 인증 전 거부된 요청은 일부 값이 없을 수 있음 |
| `input.question` | 사용자가 입력한 질문 원문 |
| `input.selection` | 요청한 교환기 ID/복수 ID·공정 코드·검사 ID |
| `scopes` | 실제 선택된 설비 코드·Tag·명칭·공정과 검사 회차·날짜·보고서 정보 |
| `excluded` | 생성 단계에서 분석 대상에서 제외된 설비와 사유 |
| `query_kind` / `period` | Tube 분석 또는 검사 횟수 질의, 검사 횟수 조회 기간 |
| `sql` / `parameters` | 화면에 제시한 생성 SQL과 바인딩 값. 검증에서 거부된 SQL도 반환된 초안이 있으면 기록 |
| `status` / `http_status` | 성공·오류 및 HTTP 상태 |
| `error.type` / `error.message` | 오류 종류와 사용자용 오류 메시지(보안 단계의 비JSON 응답은 HTTP 상태 설명). 성공하면 `null` |
| `result` | 실행 결과 행 수·조회 해시·상한 도달 여부. 결과 행 본문은 저장하지 않음 |
| `duration_ms` | 기록 처리 전까지 요청 소요 시간 |

검사 횟수 질의는 모델을 거치지 않는 기존 경로도 동일하게 기록한다. 입력 오류, 생성 중 중복 요청(429), SQL 검증 실패, CSRF/권한 거부, 만료·변조된 토큰, 실행 오류를 포함한다. 알 수 없는 서버/DB 오류는 내부 접속 정보가 섞일 수 있어 예외 종류와 사용자용 메시지만 저장한다. 서명 토큰·세션 쿠키·CSRF 값·DB 비밀번호는 요청 메타데이터로 저장하지 않는다.

실행 단계의 질문과 선택 범위는 브라우저가 다시 보낸 값이 아니라 서명 검증한 생성 요청에서 복원한다. 만료된 본인 토큰은 서명과 소유자를 확인한 뒤 오류 로그의 문맥만 복원하며 실행하지 않는다. 다른 사용자의 토큰이나 변조된 토큰의 내용은 신뢰하거나 저장하지 않는다.

정상 질문은 웹의 500자 제한 내에서 그대로 기록한다. 비정상적으로 큰 잘못된 입력은 질문/문자열 2,000자, 선택 목록 500개, 거부된 SQL 12,000자로 제한한다(`sql_truncated` 표시). 실제 실행 가능한 SQL은 기존 6,000자 제한을 유지한다.

## 저장 실패와 동시 요청

- 스레드 잠금과 운영체제 파일 잠금을 함께 사용하여 여러 스레드·프로세스의 append가 섞이지 않도록 한다. 별도 잠금 파일은 만들지 않는다.
- 기록 후 파일 동기화를 수행한다. 감지된 중간 쓰기 실패는 해당 기록만 원래 파일 길이로 되돌려 이전 정상 이력을 보존한다.
- 로그 저장에 실패한 생성·실행 결과를 성공 응답으로 반환하지 않는다. HTTP 503과 ‘사용 이력을 저장하지 못했습니다’ 메시지를 표시하고 기존 서버 오류 로그에는 안전한 예외 종류를 남긴다. 이미 실패한 조회의 오류 응답은 유지한다.
- 테스트 앱은 업무 이력에 테스트가 섞이지 않도록 `tmp/text_to_sql-test-usage/`에 기록한다. 시험에서는 `TEXT_TO_SQL_USAGE_LOG_DIR`로 IRIS2 내부의 별도 임시 경로를 지정할 수 있다.

## 읽는 방법

전체 파일을 한 번에 `json.load()` 하는 대신 줄마다 해석한다.

```python
import json
from pathlib import Path

path = Path('logs/text_to_sql/text_to_sql_2026-11.txt')
with path.open(encoding='utf-8') as stream:
    records = [json.loads(line) for line in stream if line.strip()]
```

## 검증

- `tests/test_text_to_sql_usage_log.py`: 월 경계·한글/줄바꿈·기존 이력 보존·동시 80건·4개 프로세스 동시 80건·중간 쓰기 실패 복구·토큰 미기록·생성/실행 문맥 연결·오류/권한/만료 처리 검증.
- 관련 Python 시험 112건 통과. 이전 메뉴 검사에서 일반 사용자의 상단 LLM 버튼이 없음을 현재 관리자 전용 버튼 정책에 맞게 수정했다.
- 실제 실행 중인 서버에 대한 모델 생성·MariaDB 조회·입력 오류·파일 append 확인 도구: `tools/verify_text_to_sql_usage.py`.
- 근거: `reports/text-to-sql-usage-20261112/tests.json`, `live.json`.
- 실행 중인 로컬 서버에 반영 후 실제 로컬 모델 생성·MariaDB 실행·입력 오류를 HTTP로 확인했다. `logs/text_to_sql/text_to_sql_2026-11.txt`에 생성/실행 성공 2건과 오류 1건이 완전한 JSON 객체로 저장됐으며, 같은 흐름 ID와 기존 내용 보존을 확인했다. 이후 실제 사용도 같은 월별 파일에 계속 누적된다.

# 활성 코드 재검증 — 2026-11-13

범위는 IRIS2의 활성 진입점(app.py/server.py), VCM1·VCM2 업무 경로, MariaDB 데이터 접근, 권한, 계산 및 최근 변경 사항이다. PE·VCM3·VCM4 기능을 추가하지 않았다. 아래 결과는 실행한 검증 범위의 결과이며 API/ASME 규격 전체 적합성, 현장 판정 또는 모든 잠재 오류의 부재를 인증하지 않는다.

## 발견하고 수정한 문제

1. **API 510 승인·반려의 동시 요청**: 상태 조회에 행 잠금이 없어 두 검토자가 같은 SUBMITTED 상태를 읽고 서로 덮어쓸 수 있었다. 상태를 읽기 전에 SELECT FOR UPDATE로 잠그도록 수정했다. 별도 MariaDB에서 동시에 승인·반려를 요청해 하나만 성공하고 나머지는 상태 충돌로 거절되는 것을 확인했다.
2. **계산 경계값**: 유한한 입력이어도 매우 작은 부식속도에서는 잔여수명이 Infinity가 되고, 극단적인 ASME 입력에서는 무한대·0으로 언더플로한 결과가 나올 수 있었다. 계산 중간값과 최종값을 검증하고, 지원 범위를 넘는 검사 날짜를 ValueError로 처리했다. 통상 입력의 공식은 유지했다. 네 형상에서 필요두께와 MAWP 역산 관계도 확인했다.
3. **Text-to-SQL 월 지정**: `2025년 3월`에서 월 부분이 남아 연도 전체로 잘못 해석될 수 있었다. `YYYY년 M월`을 달력 월로 해석하고, 남은 미지원 월·일 표현을 거절하도록 수정했다. 윤년·잘못된 월·날짜 추가 표현을 검증했다.
4. **대시보드 템플릿**: 별도 템플릿 렌더링에서 API 510 대기 변수가 없으면 오류가 발생했다. 변수가 정의된 경우에만 해당 영역을 표시하도록 수정했다. 대기 영역의 최하단 배치를 유지한다.
5. **검증 체계**: 일부 테스트가 MariaDB 전환 전 SQLite·이전 메뉴·특정 이메일 허용 정책을 가정했다. 현재 MariaDB, 관리자 권한 및 관리자 메뉴 위치에 맞는 테스트를 수정했다. 외부 iris/SQLite 전용 통합 테스트 세 개에는 실행 전에 명시적인 SkipTest를 두고, 별도 검증 도구에서 미전환 모듈을 통과로 집계하지 않도록 했다.
6. **백업 보관 정책**: 최종 재실행에서 파일 수정시각이 같으면 정렬 결과에 따라 새 백업이 삭제될 수 있음을 확인했다. 이번 성공 백업을 보관 목록의 첫 항목으로 고정하고 나머지는 나노초 수정시각·파일명으로 정렬한다. 동일 시각 및 수정시각 역전 조건에서 새 백업이 남는지 고정된 테스트로 검증했다.

## 데이터 보호와 검증 과정의 조치

최초 광범위 실행 중 구형 test_iris_v2가 임시 SQLite 설정 대신 기본 MariaDB를 사용해 테스트 설비 5건, 연결 번들 5건, 테스트 공정 1건을 생성했다. 생성 시각·정확한 ID·코드를 대조하고 연결 검사/튜브 이력이 없음을 확인한 뒤 해당 행을 로컬 파일로 백업하고 제거했다. 기존 공장은 제거하지 않았다. 자동 증가 번호와 변경 감지 revision은 되돌리지 않았다. 해당 테스트는 이후 실행 전 차단한다.

정리 후 일관된 백업을 생성하고 `iris2*_test_audit_20261113` 네 개의 별도 스키마로 복원했다. 상태 전환·정비·계획·사용자·동시성·ML 검토 이력 쓰기는 이 격리 환경에서 수행했다. 운영 설정 파일은 전환하지 않았다. 정리 후 백업 기준과 후속 실행 뒤 네 원본 스키마의 데이터·정의 지문이 모두 일치함을 확인했다. 원본 검사·튜브 이력에 변경은 없었다.

원시 로그, 테스트 데이터, 백업 및 화면 캡처는 로컬 tmp/reports/backups에만 보관하며 Git에 포함하지 않는다.

## 재실행

운영 DB와 별도로 복원한 테스트 스키마를 준비한 후 실행한다. 아래 이름은 이번 PC에 생성한 로컬 테스트 대상이다.

```powershell
.\.venv\Scripts\python.exe tools/validate_application.py --workflow-schema iris2_test_audit_20261113
```

스키마 인수를 생략하면 쓰기 통합 테스트는 NOT_RUN으로 남는다. 지정한 테스트 스키마가 없을 때의 Skip도 기록에 표시된다. 미전환 목록과 실행 실패는 별개이며, 미전환을 무시한 전체 성공 선언을 해서는 안 된다. 다른 PC의 DB 계정·복원 대상과 가상환경은 Git 갱신만으로 준비되지 않는다.

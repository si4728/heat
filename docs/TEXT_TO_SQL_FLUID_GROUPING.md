# Text-to-SQL 유체별 열교환기 집계

2026-11-17 · VCM1·VCM2

질문 예:

- `유체명별로 교환기 수량과 설비 목록을 보여줘`
- `Shell 유체명별 교환기 수량과 목록`
- `공정별 Tube 유체명별 교환기 수량과 목록`
- `Shell 유체명이 STEAM인 교환기 목록`

SQL 생성 후 SQL 실행을 누르면 유체명·측·열교환기 수량·설비 태그 목록을 표시한다. 현재 사양만 사용하며 검사 이력이 없는 설비도 포함한다. 선택 범위가 없으면 VCM1·VCM2 전체를 사용하고, 질문에 공정을 지정하면 선택 범위와 교집합을 적용한다. 명시한 설비 태그/코드도 선택 범위와 대조한다.

기본은 Shell·Tube 각각의 그룹이다. Head는 명시한 경우 조회한다. 같은 설비는 각 그룹 안에서 1대로 집계하므로 Shell·Tube 그룹 수량을 더해 전체 설비 수로 해석하지 않는다. `공정별`을 지정하지 않으면 선택한 공정을 합산하되 목록에는 공정을 함께 표시한다.

최신 현재 사양의 Shell·Tube 유체 필드를 우선하고 빈 값은 동일 사양의 측별 유체 필드를 사용한다. 대소문자·앞뒤 공백만 정규화하며 STEAM과 L.P.STEAM 같은 다른 이름을 임의로 합치지 않는다. 누락값은 `미등록` 그룹으로 표시한다. 과거 사양·기간·검사 결과·운전조건과 결합한 집계는 지원하지 않는다.

서버가 고정 SELECT를 생성하고 서명된 범위·조건·SQL을 실행 시 재검증한다. 전용 SELECT 계정·읽기 전용 스냅샷·5초 제한·100행 제한·기존 TEXT_TO_SQL/INSPECTIONS 권한·CSRF·사용 이력 기록을 유지한다. 101번째 그룹이 있을 때 제한 도달을 표시하며 설비 목록은 충분한 GROUP_CONCAT 길이를 설정해 조회한다.

다른 PC에서는 Git 업데이트와 별도로 로컬 iris2 가상환경에서 `tools/grant_text_to_sql_fluids.py --apply`를 실행해야 한다. 해당 도구는 기존 Text-to-SQL 계정에 사양 2개 테이블의 SELECT만 추가하며 자격증명을 변경하지 않는다. 신규 계정 설치 도구에도 동일 권한을 포함했다.

검증: 전용 계정으로 실제 MariaDB 조회, 212대의 Shell/Tube별 집계 합계 대조, STEAM 10대 확인, 유체 필터·잘못된 범위·권한 철회·SQL 변조·기간 조건 거부·기존 Text-to-SQL 회귀시험.

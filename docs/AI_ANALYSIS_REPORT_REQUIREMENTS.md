# IRIS 검사데이터 AI 분석 및 보고서 요구사항

작성일: 2026-11-07

사용자가 제공한 질문·기대 답변을 개발 및 사용자 검수 기준으로 정리한다. 이 문서는 요구사항이며 기능 구현·현장 승인 완료를 뜻하지 않는다. 개발 범위는 VCM1·VCM2이며, 제공 예시의 PVC1은 범위 확인 전 구현 대상에 포함하지 않는다. 설비 태그 E-141B·E-701은 질문 예시이며 실제 데이터 존재·수치는 검증 전 가정하지 않는다.

## 조회·계산 규칙

1. AI는 질문 해석, 제한된 분석 데이터에 대한 SQL 생성, 근거에 기반한 서술을 담당한다. 생성 SQL은 구문 트리·허용 데이터·바인딩·권한 검증을 통과한 경우에만 전용 읽기 계정으로 실행한다. 수명·검사주기는 기존 계산 서비스를 사용하며 수치를 추정하지 않는다. 사용자 요청에 따라 Text-to-SQL 방식으로 진행한다. 단계별 구현 범위와 연결 조건은 `TEXT_TO_SQL.md`를 따른다.
2. 사용자 조회 권한과 공정 범위를 데이터 조회 시 적용한다. 설비 태그가 여러 설비에 대응하면 공정·설비를 확인한다. 인식하지 못한 태그나 범위를 전체 설비 검색으로 조용히 대체하지 않는다.
3. ‘최근 검사’는 유효한 비대체 검사 중 검사일 기준 최신 회차를 먼저 확정한 뒤 그 회차만 집계한다. 검사일이 없으면 보고일 사용 사실을 표시한다. 같은 날짜의 복수 회차는 보고서·범위를 구분하며, 합본 기준이 없으면 선택을 요청한다.
4. 검사 Tube 수량은 고유 Tube 기준으로 집계한다. 보고서 기재 수량과 실제 상세 측정 수량이 다르면 둘 다 표시한다. 측정값 결측을 0으로 바꾸지 않는다. 최소두께와 최대 감육률은 서로 다른 Tube에서 발생할 수 있으므로 각각 독립 집계한다.
5. 평균 감육률은 회차 내 Tube별 유효 최대 감육률의 산술평균을 기본 제안으로 하며, 업무 승인 후 확정한다. 유효 표본 수·결측 수·계산 방식을 함께 표시하고 보고서 기재 평균과 구분한다. 이상 Tube는 승인된 관리기준으로 정의하며, 기준이 없으면 이상 수량을 확정하지 않는다.
6. 상위 Tube는 Tube별 유효 최대 감육률을 사용하고 동률은 안정적인 Tube 식별번호 순으로 정렬한다. 최소두께·위치는 해당 감육 측정 근거와 연결하며, 다른 측정 지점의 최소두께는 별도로 표시한다. 5개 미만이면 실제 개수만 답한다.
7. 이력 비교는 동일 설비·동일 설치 이력·동일 Tube를 매칭하고 측정 위치·방법의 비교 가능성을 확인한다. 교체·재관·식별 불명·위치 불일치·결측은 제외 사유를 표시한다. 과거두께 − 현재두께를 감육량으로 표시하며, 두께 증가를 임의로 0으로 바꾸거나 부식 회복으로 단정하지 않는다. 측정 불확실성을 고려할 근거가 없으면 진행 여부를 확정하지 않는다.
8. 잔여수명은 기존 공통 계산 결과를 재사용한다. 현재 산식·한도·기산 방식은 `REMAINING_LIFE_FORMULA_20261028.md`와 실제 계산 서비스에 따른다. Tube의 한도 도달 예상과 설비의 허용 Plugging 수량 초과 시점을 구분한다. 설치 후 평균 부식속도와 검사 간 부식속도를 혼용하지 않는다. 적용한 속도·출처를 명시한다.
9. 부식속도 0·음수·결측, 설치일 불명, 유효 검사 부족 등은 기존 서비스의 산정 상태와 사유를 전달한다. 산정 불가를 잔여수명 0 또는 무한대로 치환하거나 순위에 섞지 않는다. 연도만 알려진 날짜는 추정임을 표시한다.
10. Plugging 후보와 실제 조치 결정을 구분한다. Tube 감육 판정 기준과 설비 허용 Plugging 비율은 서로 다른 기준이다. 이미 Plugged된 Tube는 신규 후보와 중복 계산하지 않는다. 임의의 공통 감육률을 승인 기준으로 간주하지 않는다.
11. 차기검사는 기존 API 510 계산·승인 검사계획 등 해당 설비에 적용되는 기준을 확인한다. 설비 예측 잔여수명을 그대로 운전 허용기간이나 검사주기로 변환하지 않는다. 기준이 없으면 일자를 확정하지 않고 필요한 자료를 안내한다.
12. 공정 관리 우선순위는 승인된 순위 규칙과 동률 처리 기준을 노출한다. 미승인 종합점수·가중치는 만들지 않는다. 데이터 부족은 저위험을 뜻하지 않으며 별도 검토 목록에 표시한다.

## 공통 응답 및 보고서 형식

- 조회 범위: 공정, 설비, 검사 회차·기간, 계산 기준일.
- 결론: 질문에 대한 직접 답변과 필요한 표.
- 근거: 검사 ID, Tube ID, 보고서 번호, 원문 페이지 또는 권한이 적용되는 상세 화면 참조.
- 계산: 단위, 계산식·버전, 입력값, 적용 관리기준과 출처.
- 한계: 결측·제외 건수, 비교 불가 사유, 추정 가정, 추가 확인사항.
- 종합의견 상태: AI 작성 초안과 기술 검토·승인 완료본을 구분. 수치 검증 실패 시 승인본으로 제공하지 않는다.

표준 종합의견 틀:

> [공정/설비]의 [검사일/보고서]에서 전체 [수량]개 중 [검사수량]개 Tube를 검사하였다. 최소 잔존두께는 [값] mm, 최대 감육률은 [값]%, 평균 감육률은 [값]%([평균 기준/유효 표본 수])이다. [관리기준/출처]에 따른 검토 대상은 [수량]개이다. 주요 이상은 [Tube·측정 위치·근거]이며, 이전 검사 대비 [비교 결과 또는 비교 불가 사유]가 확인된다. 건전성 검토는 [계산 결과·적용 기준·한계]에 근거한다. 향후 [추가 검사·Plugging 기술 검토·검사계획 검토]를 권고한다. 본 문서는 기술 검토 전 AI 작성 초안이다.

값이 없는 항목은 대괄호 예시나 가짜 숫자로 출력하지 않고 ‘자료 없음’ 또는 ‘산정 불가: 사유’로 대체한다.

## 현재 코드와의 차이

- `llm_integration/natural_query.py`: 현재는 숫자 설비코드·감육률·최근순 등 제한된 조건 조회이다. E-141B 같은 태그, 8개 분석 의도, 검사 회차별 집계 및 공정별 순위를 추가 설계해야 한다. 최근순 정렬과 최근 회차만의 분석은 다르다.
- `llm_integration/report_workflow.py`: 근거 수집·검증·승인 흐름이 있으나, 현재 근거 수집은 전체 유효 검사 이력의 최대 감육 Tube에 연결된다. ‘최근 검사’ 요약에는 회차 선택과 최소두께 독립 집계가 필요하다.
- 기존 수명·검사주기 계산을 재사용하고, 새 읽기 전용 분석 서비스에서 권한·공정·회차·집계 근거를 통합한 뒤 질문 해석과 보고서 생성에 연결한다. 기존 경로나 계산식의 변경은 별도 구현·검증 대상이다.

## 수용시험

1. 위 8개 질문을 VCM1·VCM2의 검증된 표본으로 실행하고, 수치·근거를 원문 및 기존 계산 화면과 대조한다.
2. 과거 회차의 감육이 최신보다 큰 표본에서 최신 요약에 과거 최대값이 섞이지 않는다. 최소두께 Tube와 최대 감육 Tube가 다른 표본도 확인한다.
3. 중복 측정·결측·검사 없음·5개 미만·동률·회차 중복·설비 태그 중복의 응답을 검증한다.
4. Tube 교체·설치 이력 변경·측정 위치 불일치·두께 증가·부식속도 0 및 음수에서 비교·수명 결과를 확정하지 않는다.
5. 관리기준 없음·미지정 ‘이번 검사’·범위 밖 공정·권한 없는 설비에서 확인 요청 또는 명시적 제한 응답을 제공하며 다른 설비 데이터로 대체하지 않는다.
6. 계산 결과와 생성 문장의 수치·단위·근거 일치를 검증하고, 불일치 보고서의 승인을 차단한다. 초안 생성이 실제 Plugging 상태나 검사계획을 변경하지 않는다.
7. MariaDB 연결·권한 검증 후 경로를 노출한다. 테스트는 iris2 내부 `.venv/Scripts/python.exe`로 실행한다. 실제 현장 건전성 판단과 모델 승인은 별도 수행한다.

구현 순서는 회차별 검사 요약·상위 Tube, 동일 Tube 이력 비교, 기존 수명·검사계획 연결, 공정 순위·Plugging 검토, 근거 기반 종합의견 순으로 제안한다. 평균·이상 판정·우선순위의 업무 기준은 해당 기능 확정 전에 승인된 값을 확보한다.

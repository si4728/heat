# 감육 조건별 공정별 열교환기 수

지원 예: `튜브별 감육률 10% 이상인 교환기 수량은, VCM1과 VCM2로 구분해줘`.

- 감육 조건을 만족하는 **유효한 튜브 결과가 하나 이상** 있는 열교환기 수다. `COUNT(DISTINCT heat_exchanger_id)`로 집계하며 여러 튜브·회차가 일치해도 교환기는 1대다. 튜브 수나 평균 감육률 기준의 교환기 수와 구분한다.
- 공정별 1행, 공정·열교환기 수(대) 두 열을 반환한다. 선택한 공정에 조건을 만족하는 교환기가 없으면 0대로 표시한다. 차트도 이 두 행을 사용한다.
- 범위를 선택하지 않으면 VCM1·VCM2다. 화면에서 공정·설비를 선택하면 그 범위만 집계한다. 질문에 설비번호를 적는 방식의 범위 지정은 지원하지 않는다.
- 기간을 생략하면 교환기별 최근 유효 검사 또는 지정한 단일 설비 회차를 사용한다. 최근 검사일에 회차가 여러 개이면 기존의 제외/회차 지정 정책을 유지한다.
- `2025년 …`, `최근 3개월 …`, `전체 이력 …` 등 기존 기간 문법을 적용한다. 해당 기간의 유효 회차 중 조건을 만족하면 1대다. 검사일이 없으면 보고일을 사용하고 대체된 검사는 제외한다. 회차별 집계 결과를 더하지 않는다.
- 조회 가능한 유효 검사 회차가 범위 전체에 없으면 기존 정책에 따라 오류 안내하며 0대 결과를 만들지 않는다. 일부 설비가 제외되면 분석 대상·제외 설비에 표시한다.
- 이상·초과·이하·미만 및 0~100%를 지원한다. 평균/모든 튜브 조건, 복수 임계값, 추가 재질·두께 조건 등은 이 집계 유형에서 거절한다.

모델 생성에 의존하지 않는 고정 SQL 유형이다. SQL 검증에서 설비·공정 컬럼은 이 고정 집계 형태에만 허용한다. 기존 서명 토큰·사용자·권한·CSRF·15분 만료·SELECT 전용 계정·읽기 전용 트랜잭션·5초 제한과 실행 시 회차 재검증을 그대로 사용한다. 로그 유형은 `wall_loss_exchanger_count`다.

검증: 임계값/비교 연산자·모호한 요청 거절·모델 미호출·고정 SQL 계약·권한 범위·기간 적용·0대 보충 검사. 실제 MariaDB의 최근 검사 및 기간 검사 결과를 원시 튜브 행에서 Python 집합으로 독립 계산한 교환기 수와 대조했다. 브라우저에서는 기본 VCM1/VCM2 범위, 두 열 결과, 0대 및 차트 표시를 고정 응답으로 확인했다. 운영 데이터 쓰기나 모델 추론은 하지 않았다.

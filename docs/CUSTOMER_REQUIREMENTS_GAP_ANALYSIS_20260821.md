# 고객사 요구사항 대비 현재 시스템 차이 분석

- 작성일: 2026-08-21
- 대상 시스템: IRIS v3 열교환기 관리 시스템
- 운영 DB 스키마: 3.7.0
- 검토 범위: 검사 데이터 처리, 시각화 및 분석, AI 보고 기능

## 1. 종합 판단

현재 시스템은 기본 데이터 관리와 시각화 기반은 구축되어 있으나 고객 요구사항
전체 기준으로는 부분 충족 상태이다.

- 가장 완성도가 높은 기능: Tube Sheet Map
- 부분 구현: JSON 임포트, 운영 대시보드, 잔여수명 예측
- 추가 개발이 큰 기능: PDF 일괄 등록, API 510 정합화
- 미구현: 로컬 LLM 기반 보고서 자동 생성

현재 운영 DB에는 교환기 900대, 검사 객체 435건, 튜브 결과 6,067건이 등록되어
있으며 과년도 PDF 11개를 보유하고 있다.

## 3. 검사 데이터 처리 모듈

### 3.1 IRIS 검사 원본 데이터 임포트

현재 구현된 기능은 다음과 같다.

- 지정 JSON 스키마 검증
- 생산공장·공정·교환기 매칭
- dry-run
- SHA-256 중복 방지
- 트랜잭션 적재
- 품질 경고 생성
- 검사·튜브 결과·감육 평가 저장

현재 웹 화면은 JSON 파일 한 개만 처리한다. 고객이 요구하는 원본 데이터가 IRIS
장비의 전용 Raw 신호 파일이라면 현재 시스템은 지원하지 않는다. 현재 처리 대상은
PDF 내용을 구조화한 JSON이다.

추가 개발 항목:

1. 고객이 정의하는 IRIS 원본 형식 확정
2. 다중 파일·폴더·ZIP 일괄 업로드
3. 적재 작업 Queue 및 진행률
4. 실패 파일 재처리와 부분 재개
5. 동일 보고서 수정본 Upsert
6. 적재 전후 건수 대조 및 Rollback
7. 관리자 승인 후 확정 적재

### 3.2 기존 PDF 보고서 일괄 등록

현재는 정해진 폴더에서 `{연도}_1P_{공정}.pdf` 파일을 찾아 보여주는 PDF 열람
기능만 제공한다. 별도 개발 도구에 PDF 보완 코드가 있으나 기존 JSON과 PDF를 함께
사용하고 대상 파일이 코드에 고정되어 있어 범용 업로드 모듈로 볼 수 없다.

추가 개발 항목:

- PDF 다중 업로드
- PDF 원본 영구 보존 및 SHA-256 중복 검사
- 텍스트 PDF와 스캔 PDF 구분
- OCR 및 표·Tube Map 추출
- 교환기코드·검사일·튜브 결과 자동 인식
- PDF 페이지와 DB 필드 간 출처 연결
- 추출 결과 검토·수정 화면
- 승인된 데이터만 DB 반영
- 실패·경고 보고서와 재처리

현재 열린 품질 이슈는 434건이므로 PDF 자동화에는 검증·승인 Workflow가 필요하다.

## 4. 시각화 및 분석 모듈

### 4.1 운영 대시보드

현재 다음 항목이 구현되어 있다.

- 교환기·검사·튜브·결과 건수
- 미검사 설비
- 열린 품질 이슈
- 검사계획과 지연 건수
- 공정·연도별 검사 현황
- PDF 링크
- 최근 검사·적재·예정 검사

추가 개발 항목:

- 공장·공정·기간 필터
- 검사율·위험도·감육 추세 그래프
- 위험 설비 및 잔여수명 임박 설비 목록
- KPI 클릭 Drill-down
- 품질 이슈·지연 검사 알림
- 사용자별 Dashboard 구성
- 자동 갱신 또는 갱신 시각 표시
- Excel/PDF 보고 출력
- 고객 승인 KPI 정의와 UAT

### 4.2 Tube Sheet Map

현재 요구사항에 가장 가까운 기능이다.

구현된 기능:

- 연도별 검사 선택
- 동일 연도 복수 검사 범위 병합
- 동일 튜브의 최대 감육률 사용
- 감육률 연속 색상 표시
- 미검사·폐쇄·미사용 구분
- 2D/3D 전환
- 튜브 클릭 상세정보
- 튜브별 다년 이력
- 위치 보정 및 변경 이력

보완 필요 사항:

- 현재 실제 X/Y 좌표가 저장된 튜브는 0건이다.
- Row/Column 또는 추정 원형 배치를 사용하므로 실제 도면과 동일하다고 보장할 수 없다.
- 전체 튜브 수가 Tube Map에만 있는 47건과 내부 충돌 2건이 검토 대상으로 남아 있다.
- 두 연도의 변화량을 나란히 비교하는 화면이 없다.

추가 개발 항목:

1. 제작도면·Tube Layout 좌표 등록
2. 도면 이미지 위 좌표 Calibration
3. 전년도 대비 감육률 변화 색상
4. 두 연도 Side-by-side 비교
5. Map 이미지·PDF 출력
6. 미검사·추정 좌표의 명확한 표시
7. Tube 수량 충돌 승인 Workflow

### 4.3 잔여수명 자동 산출

현재 계산식은 다음과 같다.

```text
검사일 + ((공칭두께 × Plugging 감육률 - 현재 감육량) ÷ 부식속도)
```

현재 기본 설정:

- Plugging 판정 감육률: 40%
- 허용 Plugging: 전체 튜브의 10% 또는 20%
- 연도별 신규·누적 Plugging 그래프
- 부식속도 배율 What-if Simulation
- 수명 도달 연도 계산

현재의 `40% 감육 + 10/20% Plugging 허용`은 회사 관리기준 기반 로직이며 API 510
Section 7 공식 계산식으로 표시하면 안 된다. API 510 정합화를 위해 다음 항목이
필요하다.

- `t_actual`: 현재 측정두께
- `t_required`: 설계·압력·재질 기준 요구 최소두께
- 장기·단기 부식속도
- 잔여 부식여유
- API 510 잔여수명 공식
- 검사주기 상한 및 다음 검사일
- RBI 적용 여부
- 적용 기준 판·조항·알고리즘 버전
- 입력값·중간 계산·결과 Audit Trail
- 검사 엔지니어 검토·승인
- 회사 Plugging 기준과 API 510 계산 결과 분리 표시

현재 양의 부식속도를 확보한 대상은 71개 교환기·344개 튜브이므로 나머지는 데이터
부족 상태로 표시해야 한다.

## 5. AI 보고 기능

현재 시스템에는 로컬 LLM이 없다. `hx_ml.py`의 Isolation Forest 이상치 탐지는
LLM 보고서 생성과 다른 기능이다. 현재 교환기 보고서는 DB 값을 표로 표시하는 정적
HTML 인쇄 화면이며 검사결과를 해석하거나 문장 초안을 생성하지 않는다.

추가 개발 범위:

### 5.1 로컬 실행 환경

- Ollama 또는 llama.cpp 계열 런타임 검토
- 모델 파일 사내 PC 저장
- 외부 API 호출 차단
- 방화벽·프록시 차단 시험

### 5.2 보고서 생성

- 검사 개요
- 주요 감육 튜브
- 전년도 대비 변화
- Plugging 예상
- 데이터 품질 경고
- 점검·정비 권고 초안

### 5.3 신뢰성 및 업무 Workflow

- 문장별 근거 검사·Tube ID 연결
- DB에 없는 수치 생성 금지
- 수치 계산은 기존 계산 모듈에서 수행
- JSON 구조화 출력 후 문서 변환
- 초안 생성·사용자 수정·엔지니어 승인
- 버전·작성자·모델·Prompt 저장
- 승인본 PDF/DOCX 출력

### 5.4 운영 검증

- PC 사양별 응답시간
- 모델 용량과 메모리 사용량
- 외부 통신 0건 검증
- 환각·누락 평가 데이터셋

## 6. 권장 개발 우선순위

1. 고객과 IRIS 원본 데이터 형식 및 API 510 적용 정의 확정
2. PDF 일괄 업로드·추출·검토·승인 모듈 개발
3. API 510 계산 엔진과 회사 Plugging 기준 분리
4. 현재 품질 이슈 434건 정리
5. Dashboard 운영 KPI·알림 강화
6. 실제 Tube Sheet 좌표와 연도 비교 기능 강화
7. 신뢰 가능한 구조화 데이터 기반 로컬 LLM 보고서 개발

## 7. 결론

Tube Sheet Map은 보완 후 납품 가능한 수준에 가장 가깝다. PDF 일괄 등록과 로컬
LLM은 별도 신규 개발이 필요하다. 잔여수명 모듈은 화면 보완보다 계산 기준 재설계와
검사 엔지니어 승인이 우선되어야 한다.

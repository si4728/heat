# Text-to-SQL 열교환기별 결과와 로컬 종합 의견

2026-11-23 · VCM1·VCM2

기본 결과 형태를 `열교환기별 분석 결과`로 추가했다. 기존 튜브·기간·집계 조회는 결과 형태에서 선택할 수 있으며, PDF·유체 그룹·검사 횟수 질문은 기존 전용 경로를 유지한다. 이 변경으로 기존 API의 튜브 조회 계약을 일괄 변경하지 않는다.

## 열교환기 분석 결과

각 열교환기 ID는 1행이다. 공정·Tag·설비명·최근 검사일·최대 감육률·예상 잔여수명·차기 검사 권고일·산정 근거·계산 기준일을 표시한다. 원시 튜브 행을 자른 뒤 중복을 제거하는 방식이 아니라 열교환기 단위로 계산값을 연결한 후 조건·정렬·표시 개수를 적용한다.

잔여수명과 권고일은 `services.exchanger_detail(id)['remaining_life']['equipment_overview']`를 재사용한다. 분석 화면의 기본 배율·기준값과 같은 결과이며, 다른 배율로 실행한 시뮬레이션 결과나 별도 승인 API 510 일정으로 대체하지 않는다. 미산정과 한도 미도달은 해당 표시를 보존하고 0년으로 취급하지 않는다. 권고일이 없으면 결측값으로 표시한다.

전용 SELECT 계정으로 허용된 설비를 조회한 후 기존 분석 서비스를 호출한다. SQL은 설비 목록 조회에 사용하고 수명·권고일 결합 및 계산값 조건은 애플리케이션에서 처리한다. 따라서 SQL 미리보기만 단독 실행하면 전체 표시 컬럼과 계산값 필터가 재현되는 구조는 아니다. 전체 처리에 하나의 DB 스냅샷을 공유하는 것은 아니므로 조회 중 자료가 수정되면 재조회가 필요할 수 있다.

지원하는 기본 질문 예:

| 질문 | 처리 |
| --- | --- |
| 열교환기별 잔여수명과 차기 검사 권고일 | 현재 분석값으로 설비별 목록 |
| E-111 열교환기 잔여수명 | 선택 범위와 해당 Tag의 교집합 |
| 잔여수명 5년 이하인 열교환기 | 유효 잔여기간에 조건 적용. 미산정 제외 |
| 최대 감육률 30% 이상인 열교환기 | 유효 분석 튜브의 최대 감육률 기준 |
| 감육이 가장 심한 열교환기 5대 | 최대 감육률 내림차순의 서로 다른 설비 5대 |
| 평균·최소 감육률, 과거 수명 비교, 운전조건 복합 분석 | 현재 신규 경로에서는 거절. 기존 조회 또는 별도 확장 필요 |

첨부 메일 이미지의 예시 질문은 접근 불가로 확인하지 못했다. 위 표는 실제 구현 범위이며 첨부 이미지에 대한 판정표를 대신하지 않는다. 질문 문구를 받으면 별도 항목별로 확인해야 한다.

## 로컬 LLM 종합 의견

결과 표를 표시한 뒤 별도 요청으로 로컬 요약을 생성한다. 실패·시간 초과 시 표는 보존하고 다시 생성할 수 있다. 새 질문/새 결과가 표시되면 이전 요약 응답이 새 표 아래에 붙지 않도록 결과 버전을 대조한다.

기본 모델 설정은 `gemma-4-E4B-it-Q4_K_M`, 추가 등록 모델은 `Qwen3-1.7B-Q6_K`이다. 실제 요약 시험은 기본 Gemma 모델로 수행했다. 실행 시 모델 이름은 해당 PC의 `llm_integration/models.local.json`을 읽으며 모델·설정·가중치는 Git에 포함하지 않는다.

입력은 표시된 표 전체의 행 수·미산정 수·권고일 누락 수·5년 이하 설비 수와 앞 최대 10대의 상세 근거다. 따라서 모든 설비의 개별 사실을 전부 서술하는 요약이 아니다. 모델 이름과 상세 근거 범위를 화면에 표시한다. 조회 밖의 숫자와 일부 확정적 안전 표현은 검증에서 거절하지만, 자유 서술의 모든 의미적 오류를 자동 검증하는 것은 아니다. 모델 요약은 수명·권고일 계산값을 덮어쓰지 않는다.

## 권한과 실행 제한

- 기존 TEXT_TO_SQL·INSPECTIONS에 EXCHANGERS·REMAINING_LIFE 조회 권한을 추가 확인한다.
- 생성 SQL·범위·조건은 사용자에 묶어 서명하며 실행 시 허용 설비를 재확인한다.
- 종합 의견은 서버 조회 결과의 서명된 근거만 받는다. 클라이언트가 제출한 표·모델 답변을 근거로 신뢰하지 않는다. 유효시간은 15분이다.
- SQL 제한 5초, 표시 최대 100대, 모델 자식 프로세스 제한 120초다. SQL과 분석 서비스 결합 전체에 5초 제한이 적용되는 것은 아니다.
- 모델 생성은 기존 SQL 생성 작업과 잠금을 공유한다. 외부 API를 사용하지 않는다.
- 새 런타임 파일 `application/text_to_sql_equipment.py`, `application/text_to_sql_commentary.py`, `tools/summarize_text_to_sql.py`를 배포본에 포함해야 한다.

## 검증과 서비스 상태

관련 Python 회귀시험, 실제 MariaDB에서 E-111의 화면값 대조, Gemma 모델 실추론, 실제 결과/실요약을 사용한 로컬 HTML의 1440·768·390px 표시와 요약 오류 후 표 보존을 검증했다. 브라우저 검증은 네트워크 API를 로컬 검증 응답으로 대체한 화면 시험이며 운영 HTTP 서비스의 가동 검증은 아니다. 업무 파일·검증 HTML·캡처·모델 출력은 ignored 로컬 폴더에만 보관한다.

사용자의 서비스 중지 요청을 유지하여 이번 작업에서는 운영 웹 서버를 시작하지 않는다. 웹 가동과 운영 HTTP 확인은 별도 재가동 요청 후 수행한다.

# Text-to-SQL 추가 질문 구현 및 검증

2026-11-26 · PE·VCM1·VCM2 · `prod/20261126-advanced-questions`

## 적용 상태

기존 Text-to-SQL 화면에서 첨부 예시 8개를 처리하도록 확장했다. 별도 화면을 만들지 않았다. 기본 결과는 열교환기당 한 행이며, 생산팀 집계와 검사 추이는 각각 생산팀·검사 회차당 한 행이다. 설비 코드와 검사 보고서 링크로 상세 화면에 이동한다.

**기능 코드와 분리된 시험 DB 검증을 완료했고, 이후 사용자의 명시 승인에 따라 운영 Text-to-SQL 계정의 두 테이블 SELECT 권한도 적용했다.** 최초 자동 승인 검토에서는 운영 계정의 읽기 범위 확대가 차단됐으나, 사용자가 두 테이블의 SELECT 추가를 승인한 후 준비된 도구로 적용했다. 운영 웹 서비스는 중지 상태를 유지했다.

## 계산과 해석 범위

- 잔여수명·차기 검사 권고일은 기존 분석 서비스를 호출한다. 별도의 수명 공식이나 DB 스냅샷 저장은 추가하지 않았다.
- 검사 비교는 유효 결과·품질·설치·번들·대체 검사 기준을 적용한다. 같은 날짜에 복수 회차가 있거나 설치 집단이 다르면 임의 병합하지 않고 제외 사유를 표시한다. 최대값 비교의 표본 구성이 달라질 수 있으므로 동일 튜브의 부식 진행을 확정하는 값은 아니다.
- 감육속도는 분석 화면 기본 적용값 중 유효한 양수만 사용한다. 보고서 원시 속도나 사용자가 변경한 일시 시뮬레이션 값은 사용하지 않는다.
- 표본 부족은 검사 범위 확대를 검토할 근거다. 자동으로 정비나 재검사를 확정하지 않는다. IRIS 미실시 설비를 표본 0본으로 취급하지 않는다.
- 무검사 조회는 등록된 IRIS 적용 여부를 사용한다. 적용 여부 미확인·비대상 및 날짜 미상 검사 이력은 결론에서 제외하고 사유를 표시한다. 기간 경계일의 검사는 기간 내 검사에 포함한다.
- Cu-Ni는 현재 승인 Tube 사양의 Cu-Ni/CuNi 표기를 정규화한다. 과거 사양이나 Shell 재질을 대신 사용하지 않는다. 최대 감육률 미산정 설비는 수치 순위에서 제외한다.
- 생산팀 집계의 한도는 1~20% 정수, 기간은 0~100년을 지원한다. 이미 한도에 도달한 0년은 포함하고 산정 불가를 0년으로 치환하지 않는다. 도달 연도는 기준 검사·목표 날짜에서 가져오며 현재 연도에 잔여연수를 더해 과거 도달 시점을 바꾸지 않는다. 실제 계산 경계는 허용 Plugging 수량 **초과**다.
- 검사 추이는 보고서 수량과 실제 완료 원장을 구분한다. 완료 이력 미등록·날짜 미상·최초 확인 완료 이전 회차는 미확인으로 표시하고 0본으로 만들지 않는다. 취소된 완료는 실제 누적에서 제외한다. 과거 설치·부분 검사에는 표시를 붙인다. 현재 잔여수명을 과거 회차에 복사하지 않는다.
- 고급 질문은 지원하는 한 종류의 조건을 처리한다. 복합 조건·별도 기간·운전조건 등 지원하지 않는 조건은 거절해 조건이 조용히 사라지는 일을 막는다. 모든 자연어 표현을 지원하는 것은 아니다.

## 종합 의견·화면·보안

기존 서명된 조회 결과와 서버 확인 수치 문장을 사용한다. 열교환기·생산팀·검사 회차에 맞는 요약 근거를 생성해 모델이 집계 행을 설비 수로 오해하지 않도록 했다. 생산팀 집계·회차 추이의 실제 로컬 모델은 `gemma-4-E4B-it-Q4_K_M`로 검증했다. 나머지 여섯 예시의 이번 브라우저 종합 의견은 테스트 대체 모델을 사용했고, 조회·계산·HTTP·표·링크는 실제 경로였다.

기존 설비·잔여수명 권한, 사용자별 조회 토큰, CSRF, SELECT 전용 계정, FIFO 모델 대기열을 유지한다. 원시 이력 조회는 PE·VCM1·VCM2 범위 재확인, 읽기 전용 일관된 트랜잭션, 문장당 5초, 테이블별 100,000행 상한을 적용한다. 전체 범위 분석은 시험 시 약 9~11초였으며 공통 분석 계산 시간은 SQL 문장 제한과 별개다. 범위가 커지면 설비 선택으로 줄일 수 있다.

함께 수정한 경계는 실제 완료+실측 기준 도달 수가 허용 수량을 초과했는데 통계 예측으로 덮어쓰는 경우와, 무검사 설비가 완료 수량 때문에 IRIS 미실시에서 빠지는 경우다. 이전 재점검 문서의 R1·R2·R3에 해당한다. 이후 R4 생산팀 대시보드 숫자 링크, R5 사이드바 순위와 분석 입력 기준 차이 및 실측/NDD 두께 안내도 별도 순차 보완했다. 최신 상태는 [보완 기록](REQUIREMENTS_FOLLOWUPS_20261126.md)을 참고한다.

## 검증

- Python 자동 테스트 273개 통과: Text-to-SQL 218개, 고객 변경 9개, Plugging 웹 3개, 표본 추정 15개, 대시보드 9개, 단기 감육 8개, 대기열 3개, 접근 감사 8개.
- 실제 MariaDB 복제본의 합성 경계 데이터로 비교 5%p, 무효 측정 제외, 표본 9본, 보고서 수량과 실제 완료 분리, 검사 기간 경계 및 대체 이력을 검증했다.
- 차트·링크 JavaScript 회귀 통과. 실제 브라우저에서 8개 질문, 결과 단위·링크, 1440/768/390px 화면을 확인했다. 집계·이력 두 질문은 실제 로컬 모델의 3부분 의견을 확인했다.
- 복제본 시험에는 임시 SELECT 전용 계정을 생성했다가 계정·DB·임시 웹 서버를 제거했다. 이 시험 시점에는 운영 계정 권한을 변경하지 않았으며, 이후 아래 명시 승인 절차로 두 테이블의 SELECT만 추가했다. 업무 원본 데이터는 수정하지 않았다.

## 승인 후 운영 권한 적용

사용자가 두 테이블의 SELECT 추가에 명시 승인한 후 적용했다. 대상은 기존 Text-to-SQL 계정의 `iris_inspection_summary_history`, `tube_plugging_event` 두 테이블 **SELECT**뿐이다. 쓰기 권한·비밀번호·다른 계정은 변경하지 않았다. 추가로 읽을 수 있는 데이터는 검사 보고서 요약과 실제 Plugging 완료·취소 이력이다. 적용 후 기존 SELECT 전용 계정으로 이력 조회가 통과했고, 쓰기 권한이 없음을 확인했다.

승인 후 실행한 권한 도구와 운영 읽기 경로 검증 도구:

```powershell
.\.venv\Scripts\python.exe tools/grant_text_to_sql_advanced_history.py --apply
.\.venv\Scripts\python.exe tools/verify_advanced_questions_20261126.py
```

GitHub 소스 반영은 PC별 DB 권한을 자동으로 배포하지 않는다. 다른 PC에도 해당 SELECT 권한이 필요한지 별도로 확인해야 한다. 추가 질문 구현 당시에는 작업 브랜치로 게시했으며, 이후 [순차 보완 작업](REQUIREMENTS_FOLLOWUPS_20261126.md)에서 main으로 통합했다. 운영 웹 서비스는 중지 상태를 유지한다.

# 지능형열교환시스템 전체 기능 명세

- 작성 기준일: 2026-09-03
- 대상 시스템: IRIS v3 지능형열교환시스템
- 기준 소스: `C:\access\heat\iris2` 현재 코드, 화면 템플릿, 설정, 데이터 모델 및 자동화 테스트
- 주 데이터베이스: `data/heat_exchanger_db3.db`
- 현재 코드 스키마 버전: 3.9.0

## 1. 시스템 개요

본 시스템은 열교환기 자산, IRIS 검사 결과, 개별 튜브 상태, 정비 이력 및 잔여수명을 하나의 SQLite 데이터베이스에서 통합 관리하는 Flask 기반 웹 애플리케이션이다. 다년 검사 데이터의 추적, Tube Plugging 예측, API 510 검사주기 계산, 검사 원본 PDF 조회, 데이터 품질 관리, 엑셀 내보내기, 백업 및 사용자별 권한 관리를 제공한다.

핵심 관리 단위는 다음과 같다.

1. 생산공장과 생산라인
2. 설비와 열교환기 자산
3. 교환기 사양 개정과 Shell/Tube 측별 사양
4. 번들, 검사 범위 및 물리 튜브
5. 연도별 IRIS 검사와 튜브별 검사 결과
6. 튜브 위치·상태·정비 생애주기
7. 감육 추세, Plugging 예상 및 API 510 계산
8. 원본 JSON/PDF, 적재 이력 및 데이터 품질 이슈

## 2. 접속과 공통 화면

### 2.1 실행 및 접속

- 기본 실행 포트는 `4823`이다.
- 서버 바인딩 주소는 `0.0.0.0`으로 설정되어 있어 같은 네트워크의 다른 장치에서도 서버 PC의 IP와 포트로 접속할 수 있다.
- 서버 PC 자체에서는 `http://localhost:4823`을 사용한다.
- 현재 확인된 로컬 네트워크 주소 예시는 `http://192.168.0.16:4823`이다. IP는 네트워크 환경에 따라 달라질 수 있다.
- 외부 장치 접속에는 Windows 방화벽의 TCP 4823 인바운드 허용 및 동일 네트워크 연결이 필요하다.
- 운영 실행은 프로젝트 루트에서 `run.ps1`, `run.cmd` 또는 `python server.py` 방식으로 지원한다.

### 2.2 공통 레이아웃

- 좌측 사이드바에서 권한이 있는 메뉴만 표시한다.
- 상단 제목, 현재 화면의 주요 동작 버튼, 본문 영역으로 구성한다.
- 로그인 사용자의 아이디와 관리자/사용자 구분을 표시하며 해당 버튼으로 로그아웃한다.
- 현재 연결된 데이터베이스 경로와 v3 데이터베이스 상태를 사이드바 하단에 표시한다.
- 403, 404 전용 오류 화면을 제공한다.
- 숫자는 천 단위 구분 형식으로 표시한다.

### 2.3 모바일·좁은 화면 지원

- 모바일에서는 사이드바를 토글 방식으로 열고 닫을 수 있다.
- 너비가 부족한 표, 수명예측 결과, 검사 결과 및 관리 화면은 가로 스크롤로 전체 열을 조회할 수 있다.
- `.table-wrap` 계열 컨테이너에 수평 스크롤을 적용하여 표 내용이 화면 밖에서 잘리지 않도록 한다.
- 폼, 버튼 묶음, 카드 및 모달은 좁은 화면에 맞추어 줄바꿈하거나 세로 배치한다.
- 모바일 브라우저의 터치 스크롤을 지원한다.
- 로그인 버튼은 모바일에서도 동작한다. 다만 이메일 입력값이 HTML 이메일 형식에 맞지 않으면 브라우저 기본 검증이 제출을 막으므로 올바른 이메일 형식을 입력해야 한다.

## 3. 사용자 인증과 권한

### 3.1 최초 관리자 설정

- 사용자가 하나도 없는 초기 상태에서는 최초 관리자 생성 화면을 제공한다.
- 사용자명, 이메일, 비밀번호를 입력해 관리자 계정을 생성한다.
- 이메일 형식 및 길이를 검증하고 비밀번호는 최소 9자를 요구한다.

### 3.2 로그인과 세션

- 아이디와 비밀번호 기반 로그인을 제공한다.
- 비밀번호는 평문이 아닌 해시로 저장·검증한다.
- 인증이 필요한 화면에 비로그인 상태로 접근하면 로그인 화면으로 이동한다.
- 세션 유휴 제한과 영구 세션 수명은 기본 30분이다.
- 세션 쿠키는 `HttpOnly`, `SameSite=Lax`로 설정되어 있다.
- 브라우저의 데이터 변경 요청에는 CSRF 토큰 검증을 적용한다.

### 3.3 화면별 권한

다음 화면 키별로 조회와 편집 권한을 분리해 관리한다.

| 권한 키 | 대상 기능 |
|---|---|
| `DASHBOARD` | 대시보드 |
| `EXCHANGERS` | 교환기 목록·상세·입력·튜브·보고서·맵 |
| `REMAINING_LIFE` | Tube Plugging 예측·시뮬레이션·API 510 |
| `INSPECTIONS` | 검사 목록·상세·계획·PDF |
| `MAINTENANCE` | 작업지시·정비 이력 |
| `QUALITY` | 데이터 품질 이슈 |
| `PLANT_LINES` | 공장·생산라인 마스터 |
| `WALL_LOSS_COLORS` | Wall Loss 색상 기준 |
| `JSON_IMPORT` | JSON 검사 데이터 적재 |
| `EXCEL_EXPORT` | 관리 데이터 엑셀 내보내기 |

- 관리자는 모든 화면을 조회·편집할 수 있다.
- 일반 사용자는 관리자가 부여한 화면별 조회/편집 권한을 적용받는다.
- 편집 권한은 해당 화면의 조회 권한을 포함한다.

### 3.4 사용자·권한 관리

- 위치: `기본 설정 → 사용자·권한 관리`
- 관리자만 접근할 수 있다.
- 사용자 신규 생성, 활성/비활성, 관리자 지정 및 비밀번호 변경을 지원한다.
- 사용자별 화면 조회/편집 권한을 설정한다.
- 사용자별 PDF 열기 방식을 관리한다.

### 3.5 내 기본 설정

- 위치: `기본 설정 → 내 기본 설정`
- 사용자가 검사 Sheet PDF를 여는 방식을 직접 선택할 수 있다.
  - 현재 창에서 열기
  - 새 창/새 탭에서 열기
- 초기값은 `새 창/새 탭에서 열기`이다.
- 설정값은 사용자 계정별로 데이터베이스에 저장되며 다음 로그인에도 유지된다.

## 4. 대시보드

- 위치: `대시보드`
- 관리 중인 교환기, 물리 튜브, 검사 이력, 데이터 품질 이슈 등 핵심 건수를 카드로 표시한다.
- 생산라인별·연도별 검사 횟수, 검사 교환기 수, 튜브 결과 수를 표로 제공한다.
- 해당 연도/생산라인에 원본 합본 PDF가 있으면 PDF 조회 링크를 표시한다.
- 최근 검사 이력에서 검사 상세 화면으로 이동할 수 있다.
- 예정 검사를 표시하고 검사 계획 관리 화면으로 연결한다.
- 최근 JSON 적재 배치와 처리 결과를 확인할 수 있다.

## 5. 교환기 관리

### 5.1 교환기 목록

- 위치: `교환기 관리 → 교환기 목록`
- 생산공장, 생산라인, 설비코드, 교환기코드, 설비명, 공정 중요도, IRIS 적용 여부, 검사 상태, 검사 횟수, 검사 Sheet 및 튜브 마스터 상태를 표시한다.
- 공장, 생산라인, IRIS 적용 여부, 검사 상태와 검색어로 조회할 수 있다.
- 허용된 열 기준으로 안전한 정렬과 오름차순/내림차순 전환을 제공한다.
- 설비코드 또는 교환기코드를 선택해 상세 화면으로 이동한다.
- 검사 이력이 있고 연결 가능한 PDF가 존재하면 연도별 검사 Sheet PDF 링크를 표시한다.
- PDF 링크에는 검사 데이터에 매핑된 합본 PDF의 해당 교환기 시작 페이지가 반영된다.
- 사용자의 PDF 열기 기본 설정에 따라 현재 창 또는 새 창/새 탭에서 연다.

### 5.2 교환기 입력·수정

- 위치: `교환기 관리 → 교환기 입력`, 또는 교환기 상세의 수정 기능
- 사전에 등록된 생산공장과 생산라인을 선택해 신규 교환기를 등록한다.
- 설비코드, 교환기코드, 설비명, 서비스, 공정 중요도, IRIS 적용 여부, 검사 상태와 기본 사양을 관리한다.
- 공장+생산라인+설비의 자연키와 코드 중복을 검증한다.
- 미등록 공장·생산라인 코드는 저장하지 않는다.
- IRIS 미적용 자산도 검사 자산과 구분하여 관리할 수 있다.
- 교환기 형식 원본값과 표준 형식 매핑 상태를 함께 보존한다.
- FTS 등 검토가 필요한 형식은 자동 확정하지 않고 검토 대상으로 유지한다.

### 5.3 교환기 상세

- 위치: `교환기 관리 → 교환기 목록 → 설비 선택`
- 공장/라인, 설비명, 서비스, 검사 수, 물리 튜브 수 및 검사 범위 수를 요약한다.
- 자산 상태, IRIS 적용 여부, 검사 생애주기, 튜브 마스터 상태 및 형식 매핑 상태를 표시한다.
- 번들과 검사 범위를 표시한다.
- 최신 기술 사양 개정, 측별 최대 설계/운전 압력·온도, 재질, 유체, 튜브 외경·공칭두께·길이, 도면 및 Data Sheet 번호를 조회한다.
- Shell 유체, Tube 유체, Tube 재질을 빠르게 수정할 수 있다.
- 허용 Plugging, 주의/위험 감육률, 최소 허용 두께 및 검사 주기 등의 관리 기준을 표시한다.
- 2D/3D Tube Map, 튜브 관리, 출력 보고서, 잔여수명 시뮬레이션, API 510 계산 관리로 이동한다.
- 연도별 검사 이력과 최대 감육률을 확인하고 검사 상세로 이동한다.

### 5.4 사양 개정 관리

- 열교환기 사양을 개정번호와 유효기간으로 이력 관리한다.
- 개정 당시의 교환기코드를 복사해 보존하므로 이후 마스터 코드 변경의 영향을 받지 않는다.
- Shell/Tube/Head 측별 압력, 온도, 재질 및 유체 정보를 별도 관리한다.
- 최신 유효 개정을 현재 기술 사양으로 조회한다.
- 설비 용량, 규격 준수 정보, 도면 및 데이터시트 근거를 구조화한다.

### 5.5 번들·검사 범위·튜브 마스터

- 교환기별 번들과 번들 생애주기 번호를 관리한다.
- 전체, 방향, 구역 등 검사 범위를 별도 객체로 관리한다.
- 물리 튜브의 튜브번호, 행, 열, 현재 상태 및 2D/3D 좌표를 관리한다.
- 튜브 마스터가 없는 자산과 구성 완료 자산을 상태로 구분한다.
- 튜브 일괄 상태 변경과 개별 상태 변경을 제공한다.
- `IN_SERVICE`, `PLUGGED`, `UNUSED` 등 운전 상태를 검사 결과 상태와 분리하여 관리한다.
- 상태 변경 시 이전값, 새값, 사유 및 시각을 생애주기 이벤트로 남긴다.

## 6. 검사 관리

### 6.1 검사 목록 및 검색

- 위치: `검사 관리`
- 연도, 공장/생산라인, 교환기, 검사 상태 등의 조건으로 다년 검사 데이터를 조회한다.
- 검사일, 보고일, 보고서번호, 범위, 결과 수 및 상태를 표시한다.
- 목록에서 검사 상세와 원본 PDF로 이동할 수 있다.

### 6.2 검사 상세

- 검사일/보고일, 설치·교체일자 원문과 정밀도, 제작일, 가동일, 공정, 생산라인, Shell/Tube 유체 및 Tube 형식을 표시한다.
- JSON에서 분리한 원본 Bundle/Scope 정보를 보존·표시한다.
- 검사 수행업체, 계약번호, 작업지시번호, 검사 절차서와 개정번호를 관리한다.
- 검사장비, 탐촉자, 일련번호, 교정일, 교정 유효기간을 관리한다.
- 데이터 취득 및 분석 소프트웨어 이름과 버전을 관리한다.
- 검사자, 판독자, 작성자 소속 정보를 관리한다.
- 검사 당시 정보는 별도 실행 스냅샷으로 보존한다.
- 튜브별 행/열, 최소두께, 설계두께, 감육깊이, 감육률, 보고 손상률, 결함코드, 부식유형, 위치 및 비고를 조회한다.
- 검사별 검증 이슈를 함께 표시한다.

### 6.3 검사 Sheet PDF 조회

- 검사 원본 PDF는 브라우저 내장 PDF 뷰어를 사용해 인라인으로 제공한다.
- 위치는 다음과 같다.
  - `교환기 관리 → 교환기 목록 → 검사 Sheet`
  - `교환기 상세 → 검사 이력`
  - `검사 관리 → 검사 상세/원본 PDF`
  - `대시보드 → 생산라인별·연도별 검사 현황`
- 검사와 연도/생산라인 합본 PDF를 연결하고 원본 페이지 매핑을 사용한다.
- 경로 조작을 방지하기 위해 허용된 PDF 루트 내부 파일만 제공한다.
- 사용자의 `내 기본 설정`에 따라 현재 창 또는 새 창/새 탭에서 연다.
- 기본 동작은 기존 화면을 유지하는 `새 창/새 탭`이다.

### 6.4 검사 계획

- 검사 예정일, 검사 방법, 교환기 및 상태를 등록·관리한다.
- 계획 상태를 변경할 수 있다.
- 예정 검사는 대시보드에 표시된다.
- 일정 산정 시 정의된 평일/업무일 규칙을 적용한다.

### 6.5 튜브 상세와 다년 이력

- 튜브 기본정보, 현재 운전 상태 및 좌표를 표시한다.
- 동일 물리 튜브의 연도별 측정 결과를 시간순으로 비교한다.
- 최소두께, 감육량, 감육률, 결함, 위치 및 검사 방향을 보존한다.
- 동일 날짜에 여러 측정값이 있으면 최소두께와 최대 감육값을 보수적으로 사용한다.
- 검사 방향 표기를 정규화하고 물리 위치 차이가 설정 허용값 이내인 데이터만 부식속도 계산에 사용한다.
- 위치가 없거나 허용거리보다 먼 값은 감사 추적을 위해 보존하되 부식속도에서는 제외한다.

## 7. 2D/3D Tube Map

- 위치: `교환기 상세 → 2D/3D Tube Map`
- 교환기와 검사연도 기준으로 튜브 배열을 시각화한다.
- 2D와 3D 표시 모드를 제공한다.
- 감육률 구간별 색상 그라데이션을 적용한다.
- Plugged, 미사용 및 미검사 튜브는 고정 상태색으로 구분한다.
- 2D 배열에서 원주각이 등록된 결함은 튜브 원주상의 방향 마커로 표시한다.
- 한 튜브에 결함 지시가 여러 건이면 결함 건수 배지를 표시한다.
- 범례에 각 색상과 상태의 의미를 표시한다.
- 3D 맵은 회전 슬라이더와 15도 단위 회전 버튼을 제공한다.
- 튜브 위치를 드래그해 조정하고 좌표를 저장할 수 있다.
- 3D 전체 배열에서 축 방향 위치가 등록된 모든 결함 지시를 컬러 밴드로 표시한다.
- 원주각이 등록된 결함은 3D 튜브 표면의 방향 표식으로 함께 표시한다.
- 선택한 튜브를 단일 3D 모델로 분리해 실제 길이 비율, 25% 간격 눈금, 다중 결함 위치 및 결함 길이를 확인한다.
- 선택 튜브의 축 위치, 위치 기준, 원주각, 측정두께, 감육깊이, Wall Loss, 결함 길이, 판정, 검사 범위와 일자를 상세표로 제공한다.
- 상세 결함 데이터와 대표 튜브 결과를 구분하고, 위치 기준이 없으면 임의 추정하지 않고 `기준방향 미등록` 또는 `위치 미확인`으로 표시한다.
- 각 검사값에서 원본 검사 PDF의 출처 페이지를 바로 열 수 있으며 사용자별 PDF 열기 설정을 적용한다.
- 개별 튜브를 선택해 상세 이력으로 이동할 수 있다.
- Three.js 및 제어 라이브러리는 로컬 정적 자산으로 제공되어 외부 CDN 의존을 줄였다.

## 8. Tube Plugging 예측과 잔여수명

### 8.1 대상연도 검색

- 위치: `교환기 관리 → Tube Plugging 예측`
- Plugging 예상 연도, 생산라인 및 교환기 검색어로 대상 튜브를 조회한다.
- 공정 중요도, 튜브 위치, 감육률, 현재두께, 단기/장기/적용 부식속도, 기준 검사일, 예상연도 및 잔여수명을 표시한다.
- 기본 Plugging 판정 기준은 공칭두께 대비 감육률 40%이다.

### 8.2 부식속도 산정

- 단기 부식속도는 최근 비교 가능한 양의 감육 변화 구간을 기준으로 산정한다.
- 장기 부식속도는 비교 가능한 전체 기간의 두께 변화와 경과연도를 사용한다.
- 적용 부식속도는 단기와 장기 중 보수적인 큰 값을 사용한다.
- 동일 날짜 복수 결과, 검사방향 정규화 및 측정 위치 허용오차 100 mm를 반영한다.
- 계산에 채택한 값과 제외 사유를 구분해 추적할 수 있다.

### 8.3 Plugging 도달일 계산

기본 계산 개념은 다음과 같다.

`Plugging 도달일 = 최근 측정일 + (허용 감육량 - 현재 감육량) ÷ 적용 부식속도`

- 허용 감육량은 `공칭두께 × Plugging 판정 감육률`이다.
- 최근 측정일을 계산 기산일로 사용한다.
- 연도별 신규 및 누적 Plugging 수를 예측한다.
- 전체 튜브 수와 허용 Plugging 비율로 허용 개수를 계산한다.
- 누적 예상 수가 허용 개수에 도달하는 연도를 교환기 수명 도달 연도로 제시한다.
- 이미 Plugged인 튜브와 향후 도달 예상 튜브를 함께 반영한다.
- 계산 가능, 예측기간 내 한도 미도달, 데이터 부족 상태를 구분한다.
- 산정 불가 시 공칭두께, 다년 측정, 양의 부식속도 등 부족한 요건을 안내하는 도움말을 제공한다.

### 8.4 What-if 시뮬레이션

- 위치: `교환기 상세 → Tube Plugging 예측 시뮬레이션` 또는 전용 시뮬레이션 화면
- 허용 Plugging 한도를 1~20%에서 선택한다. 기본값은 20%이다.
- Plugging 판정 감육률을 변경할 수 있다.
- 현재 부식속도의 50~300% 배율을 적용해 가상 조건을 비교한다.
- 예측 종료연도를 설정한다.
- 현재 기준과 시뮬레이션의 연도별 누적 Plugging을 비교한다.
- 시뮬레이션 입력과 결과는 데이터베이스에 저장하지 않는다.
- 잘못된 형식의 날짜 문자열은 숫자 기반 정규화를 거쳐 `YYYY-MM-DD`로 보정하며 보정 불가 값은 사용자에게 한글 오류로 안내한다.

## 9. API 510 계산 관리

### 9.1 압력경계 부품 관리

- 위치: `교환기 상세 → API 510 계산 관리`
- Shell, Tube, Head 등 압력경계 부품별 코드를 등록한다.
- 지원 형상은 원통형 Shell, 구형 Shell, 2:1 타원형 Head, 반구형 Head이다.
- 내경, 설계압력, 정수두, 설계온도, 재질, 허용응력, 용접효율, 추가 필요두께, 원 설계 부식여유, 실제두께와 측정일을 관리한다.
- 실제두께 출처와 승인 설계근거 문서번호/개정번호를 필수 근거로 관리한다.
- 적용 코드 판본을 기록한다.

### 9.2 ASME Section VIII Division 1 계산

- 형상별 ASME VIII-1 식으로 필요두께를 계산한다.
- 원통형 Shell: UG-27(c)(1)
- 구형 Shell: UG-27(d)
- 2:1 타원형 Head: UG-32(d)
- 반구형 Head: UG-32(f)
- 설계압력과 정수두, 내경, 허용응력 및 용접효율을 반영한다.
- 필요두께와 현재 실제두께를 기반으로 MAWP를 계산한다.
- 입력값과 계산결과를 JSON 스냅샷으로 보존한다.

### 9.3 API 510 잔여수명·검사주기

잔여수명은 다음 개념으로 계산한다.

`잔여수명 = (실제두께 - 필요두께) ÷ 적용 부식속도`

- 단기/장기 부식속도와 사용자가 선정한 적용 부식속도를 함께 기록한다.
- 적용 속도를 비워두면 단기와 장기 중 큰 값을 사용한다.
- 검사주기는 `잔여수명 × 0.5`와 검사유형별 최대주기 중 짧은 값을 사용한다.
- 내부/가동중 검사의 기본 최대주기는 10년이다.
- 외부검사의 기본 최대주기는 5년이다.
- 최근 검사일을 기준으로 다음 검사일을 계산한다.
- 기본 코드 표기는 `API 510 11th Edition (2022), Errata 1 (2023), Errata 2 (2025)`이다.
- 실제 적용 전에는 소유자/사용자의 승인 설계계산서, 라이선스 코드 판본 및 관할 요건과 대조해야 한다.

### 9.4 검토·승인 워크플로

- 계산 상태는 `DRAFT → SUBMITTED → APPROVED` 또는 `REJECTED`로 전이한다.
- 승인과 반려는 관리자만 수행할 수 있다.
- 계산 입력, 결과, 작성자, 검토자, 처리시각 및 검토 의견을 이력으로 보존한다.
- 승인 전 계산값과 승인된 설계근거를 대조했음을 확인하도록 한다.

## 10. 정비 관리

### 10.1 작업지시

- 위치: `정비 관리`
- 교환기별 작업지시 목록을 작업번호, 공장/라인, 설비, 작업유형, 상태 및 제목으로 표시한다.
- 신규 작업지시에는 교환기, 제목, 작업유형, 우선순위 및 계획일을 입력한다.
- 작업번호를 고유하게 자동 생성한다.
- 상태는 `REQUESTED`, `APPROVED`, `IN_PROGRESS`, `COMPLETED`, `CANCELLED`를 지원한다.
- 상태 변경과 작업 결과를 저장한다.

### 10.2 정비·교체·Plugging 이력

- 작업 유형은 `MAINTENANCE`, `REPLACEMENT`, `PLUGGING`을 지원한다.
- 교환기 전체 작업 또는 해당 교환기에 등록된 특정 튜브 작업으로 기록한다.
- 다른 교환기의 튜브나 잘못된 튜브 ID 등록을 차단한다.
- 선택 목록에서 이미 `PLUGGED` 상태인 튜브를 제외할 수 있다.
- 작업과 함께 튜브 상태를 `IN_SERVICE`, `PLUGGED`, `UNUSED`로 변경할 수 있다.
- 변경 전/후 상태, 작업일시 및 상세내용을 이력으로 남긴다.

## 12. JSON 적재와 데이터 정규화

### 12.1 JSON 로드

- 위치: `교환기 관리 → JSON 로드`
- 생산공장과 해당 공장의 생산라인을 명시적으로 선택한 뒤 JSON을 업로드한다.
- 화면에서 선택한 공장/생산라인을 JSON 내용이나 파일명 추정보다 우선 적용한다.
- 최대 업로드 크기는 50 MB이다.
- Master에 존재하는 공장+생산라인+교환기만 검사 이력을 저장한다.
- Master에 없는 교환기는 신규 자산으로 자동 생성하지 않고 제외 내역을 표시한다.
- 검증만 수행하고 DB를 변경하지 않는 Dry-run을 지원한다.

### 12.2 검증 및 적재 절차

1. JSON 구조, 필드 변형, 수량 및 계산값을 검증한다.
2. 오류와 경고를 개별 JSON/Markdown 및 누적 보고서로 기록한다.
3. 전체 적재를 트랜잭션으로 처리하여 중간 실패 시 불완전한 데이터가 남지 않도록 한다.
4. 다년 검사 이력을 동일 물리 튜브에 연결한다.
5. 적재 후 감육 추세와 열화 평가를 재계산한다.

### 12.3 정규화 및 추적성

- 설비코드 뒤의 방향, 괄호 표현, 공백 구분 및 번호 구역을 검사 범위로 분리한다.
- 명시된 Bundle/Scope가 있으면 추정보다 우선한다.
- 숫자 0을 결측값으로 바꾸지 않고 유효값으로 보존한다.
- 불완전한 설치일은 원문과 연/월/일 정밀도를 함께 보존한다.
- 원본 파일, SHA-256 해시, 적재 배치, 원본 문서 페이지 및 데이터 출처를 추적한다.
- 동일 원본의 재적재에서도 중복을 방지하고 다년 적재의 멱등성을 유지한다.
- 적재 결과 화면과 모달에서 전체/신규/기존 교환기 수, 보고서 수, 튜브 결과 수, 오류·경고 수 및 열화평가 수를 표시한다.

## 15. 데이터베이스 상태 점검과 백업

### 15.1 DB 상태 점검

- 위치: `기본 설정 → DB 상태 점검`
- 관리자만 접근할 수 있다.
- 데이터베이스 파일 경로, 크기, 스키마 버전, Journal 모드와 기본 상태를 표시한다.
- SQLite `integrity_check`와 외래키 위반 검사를 수행한다.
- 최근 데이터베이스 잠금 오류를 최대 100건까지 표시한다.
- 잠금 발생시각, 작업, 프로세스 및 오류내용을 집계한다.
- SQLite WAL 모드와 30초 busy timeout을 사용해 동시 접근 안정성을 높인다.

### 15.2 백업 관리

- 위치: `기본 설정 → 백업 관리`
- 관리자만 접근할 수 있다.
- 수동 백업과 자동 백업을 지원한다.
- 자동 백업은 매일 또는 매주, 실행시간과 요일을 지정할 수 있다.
- 보관 개수를 1~365 범위에서 설정하고 오래된 백업을 정리한다.
- SQLite 온라인 백업 방식으로 일관된 사본을 생성한다.
- 백업 후 무결성 검사와 SHA-256 확인정보를 기록한다.
- 최근 100건의 시작시각, 구분, 성공 여부, 파일, 크기, 무결성, 요청자 또는 오류를 표시한다.
- 보관 중인 백업 파일의 경로, 크기 및 생성시각을 조회한다.

## 16. HTTP API와 상태 확인

### 16.1 상태 확인 API

- `GET /api/health`
- 애플리케이션, 데이터베이스 경로, 스키마 및 기본 상태를 확인한다.

### 16.2 조회 API

- `GET /api/v1/exchangers`: 교환기 목록 조회
- `GET /api/v1/exchangers/{id}/history`: 특정 교환기의 다년 검사·튜브 이력 조회
- 브라우저 화면과 동일한 화면 권한 정책을 적용한다.

### 16.3 쓰기 API

- `POST /api/v1/exchangers`: 교환기 생성
- `PUT /api/v1/exchangers/{id}`: 교환기 수정
- `X-IRIS-API-Token` 헤더로 별도 쓰기 토큰을 검증한다.
- 설정의 쓰기 토큰이 비어 있으면 쓰기 API는 비활성화되고 503을 반환한다.

### 16.4 Tube Map API

- 교환기별 Tube Map 데이터를 JSON으로 제공한다.
- 튜브 위치 저장 API를 통해 조정된 좌표를 반영한다.

## 20. 현재 운영 시 확인사항

- 코드와 주 데이터베이스는 스키마 3.9.0 기준이다.
- 기존에 실행 중이던 서버 프로세스가 3.8.0 코드를 메모리에 유지하고 있다면 서버를 재시작해야 사용자별 PDF 열기 설정과 최신 화면 변경이 반영된다.
- 다른 PC와 모바일 접속은 서버 PC 방화벽에서 TCP 4823 인바운드가 허용되어야 한다.
- 공용 인터넷에 직접 노출하기보다 사내 신뢰 네트워크 또는 리버스 프록시·TLS·접근통제가 구성된 환경에서 운영해야 한다.
- 현재 `session_cookie_secure=false`이므로 HTTPS 운영 전환 시 `true` 적용을 검토해야 한다.
- 쓰기 API 토큰은 기본적으로 비어 있어 외부 API를 통한 생성·수정이 비활성화되어 있다.
- API 510/ASME 계산값은 기술 검토 지원 기능이며 승인 설계계산서와 법규·코드 요건을 대체하지 않는다.

# IRIS2 개발·데이터 정비 종합 정리

- 작성일: 2026-10-23, 한국 시간 기준
- 프로젝트: `C:/access/heat/iris2`
- 기준: 현재 소스 코드, 이 대화에서 수행한 개발·데이터 작업, 기존 전환 문서, 작성 시점 MariaDB 재조회
- 목적: 구현 내용, 운영 방법, 집계 의미, 검증 근거와 남은 확인 사항을 한 문서에 정리한다.

## 1. 적용 범위와 독립 실행 원칙

IRIS2는 기존 IRIS와 분리된 MariaDB 기반 애플리케이션이다.

- 개발·실행·설정·보고서·백업은 IRIS2 경계 안에서 관리한다.
- 기존 `iris`의 소스·환경·운영 DB를 수정하거나 런타임에서 가져오지 않는다.
- Python 실행과 시험은 `.venv/Scripts/python.exe`를 사용한다.
- 활성 진입점은 `server.py`, 애플리케이션 생성은 `app.py`이다.
- 웹 기본 포트는 4824, 독립 MariaDB는 127.0.0.1:3307이다.
- MariaDB 장애 시 SQLite로 대체하지 않는다.
- 신규 업무 개발·현장 확인 범위는 VCM1·VCM2이다. 기존 다른 공정 데이터는 보존하며, 전체 집계와 사용자가 요청한 Master 목록 대조에는 포함한다.
- 이번 문서는 기술 구현·검증 결과이며, 현장 인수·공학 승인·모델 운영 승인 완료를 의미하지 않는다.

관련 원칙: [애플리케이션 경계](../APPLICATION_BOUNDARY.md), [MariaDB 개발 계획](MARIADB_DEVELOPMENT_PLAN.md).

## 3. 서버 실행 및 MariaDB 시작 개선

### 3.1 연결 거부 문제 처리

`run.cmd` 실행 당시 독립 MariaDB가 실행되지 않아 127.0.0.1 접속이 거부되던 문제를 확인했다.

현재 실행 순서:

1. `run.cmd`가 `run.ps1`을 호출한다.
2. 일반 실행에서는 `start_mariadb.ps1`이 3307 리스너를 확인한다.
3. 이미 실행 중이면 실행 파일·설정이 IRIS2 인스턴스인지 확인한다.
4. 중지되어 있으면 기존 IRIS2 인스턴스를 시작하고 준비 상태를 기다린다.
5. DB 시작에 실패하면 웹 서버를 시작하지 않는다.
6. 준비되면 IRIS2 전용 Python으로 웹 서버를 실행한다.

`-HealthCheck`는 의존성을 시작하지 않고 현재 상태를 점검한다. 직접 `server.py`를 실행할 때는 MariaDB를 먼저 시작해야 한다.

### 3.2 실행 명령

```powershell
cd C:\access\heat\iris2
.\run.cmd
```

같은 네트워크의 다른 PC에 웹 서비스를 제공하려면:

```powershell
.\run.cmd -ListenHost 0.0.0.0
```

- 다른 PC 접속 주소: `http://서버PC의IPv4주소:4824`
- Windows 방화벽의 TCP 4824 접근 허용은 별도 설정 사항이다.
- MariaDB 3307 포트를 다른 PC에 공개할 필요는 없다.
- 방화벽 규칙을 이번 작업에서 추가했다는 뜻은 아니다.

상태 점검:

```powershell
.\run.cmd -HealthCheck
```

기존 재시작 도구:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\restart_iris2.ps1
```

`restart_iris2.ps1`은 현재 소스 기준 127.0.0.1로 시작하므로, LAN 공개 상태가 필요하면 종료 후 `run.cmd -ListenHost 0.0.0.0`으로 실행한다.

### 3.3 서버 상태

대화 중 요청에 따라 IRIS2 웹 서버를 여러 차례 종료했고, 그 과정에서 MariaDB는 유지했다. **문서 작성 시점에는 웹 포트 4824가 `0.0.0.0`에서 수신 중임을 확인했다.** 이 문서 작성 작업은 서버를 시작하거나 종료하지 않았다.

실행 중인 프로세스가 최신 Python·템플릿을 모두 다시 읽었다고 보장하지는 않는다. 최종 소스 반영은 서버 재시작과 브라우저 새로고침으로 확인한다.

## 6. 모든 집계의 등록 설비 기준 통일

대시보드 집계는 현재 `heat_exchanger`에 등록된 설비를 기준으로 연결한다.

- 열교환기 수와 공정별 합계는 현재 등록 목록에서 계산한다.
- 현재 사양의 Tube 수만 사양 합계에 사용한다.
- 검사이력·검사결과·검사계획·품질 이슈는 등록 설비에 연결된 자료로 범위를 제한한다.
- Tube 정보와 재검사 비교도 등록 설비에 연결된 Tube 기준으로 계산한다.
- 열교환기 `대`, Tube `개`, 검사·계획 `건`, 재검사 `비교쌍`을 구분한다.
- 과거 보고서의 수량이나 과거 사양을 현재 사양 수량과 중복 합산하지 않는다.

검증: 공정별 합계, 등록 설비 입력률 대상 수, 위험도 목록 수가 모두 900대와 일치함을 확인했다.

## 7. 대시보드와 Tube 입력률 개선

### 7.1 상단 미등록 설비 현황

대시보드 최상단에 다음을 추가했다.

- 현재 등록 900대 중 수량 미등록 651대 표시
- 수량 사양 등록 249대와 등록 비율 표시
- 공정별 미등록 수량 표시
- 펼쳐서 볼 수 있는 미등록 전체 목록
- 공정·설비코드·Tag·설비명 검색
- 설비 상세 화면 연결
- 개별 Tube 등록 설비 118대와 미등록 설비 782대 표시

### 7.2 두 종류의 비율 구분

**사양 수량 대비 개별 Tube 등록 현황**은 `2,253 / 69,105 = 약 3.3%`이다. 굵은 제목, 큰 비율, 진행 막대와 등록·미등록 수량으로 강조한다.

**등록 Tube 정보 완성도**는 이미 개별 등록된 2,253개의 입력 상태를 평가한다. 위 등록률과 분모가 다르다.

### 7.3 최종 입력률

| 표시 항목 | 충족 Tube / 등록 Tube | 비율 |
|---|---:|---:|
| 번호·운전상태 | 2,253 / 2,253 | 100.0% |
| 행·열 좌표 | 2,253 / 2,253 | 100.0% |
| 2D·3D 위치 | 1,268 / 2,253 | 56.3% |
| 설치일자 | 2,253 / 2,253 | 100.0% |
| 검사이력 보유 | 2,174 / 2,253 | 96.5% |
| 최소두께 측정이력 | 2,155 / 2,253 | 95.7% |

종합 완성도는 번호와 상태를 각각 한 항목으로 계산하므로 **6개 표시 그룹, 7개 입력 항목**이다.

- 입력된 항목: 14,609칸
- 가능한 항목: 2,253 × 7 = 15,771칸
- 종합 완성도: **92.6%**
- 7개 항목을 모두 충족한 Tube: **1,259개**

입력 완료는 실측값의 정확성·원본 검증·공학적 적합성 완료를 뜻하지 않는다.

### 7.4 Pass 제외

Tube별 Pass는 개별 Tube가 속한 Tube측 유체 통과 구간을 뜻한다. 사용자의 요청에 따라 **Tube 입력률 항목과 종합 완성도에서 제외**했다. 저장 필드와 기존 데이터는 유지한다. 열교환기 사양의 총 Pass 수 항목을 삭제한 것은 아니다.

### 7.5 유효성·조회이력 구분

- 검사이력 입력 여부는 `VALID` 결과가 1건 이상 있는지를 확인한다.
- 유효 최소두께 이력은 `VALID` 결과 중 0보다 큰 두께가 있는지를 확인한다.
- 공간좌표는 직접 X/Y 또는 Tube ID에 연결된 승인·검증 Layout 좌표를 기준으로 한다.
- 미검사·미등록 값을 자동 생성하지 않는다.
- 동일 위치 재검사는 별도 비교 지표로 표시하고 종합 입력률에서 제외한다.

설치 이전 이력 제외 후 동일 위치 재검사 집계는 **709 / 3,516 비교쌍, 20.2%**이다. 과거 보고서의 752 / 3,855, 19.5%는 이전 기준 기록이다.

## 8. 설치일 처리와 과거 검사이력의 최종 기준

### 8.1 Tube 설치일 적용 확인

사용자가 장비 설치일을 Tube 설치일로 적용하도록 요청했다. VCM1·VCM2 등록 Tube 2,174개를 조회한 결과 이미 장비 설치일과 모두 일치해 추가 덮어쓰기는 없었다. 전체 등록 Tube 2,253개에도 설치일 값은 존재한다.

도구: `tools/apply_tube_installation_dates.py`. 기본은 조회이며 `--apply` 시 변경 전 백업과 트랜잭션 검증을 수행한다.

장비 설치일 변경이나 신규 Tube 생성 시 자동 동기화하는 기능을 추가한 것은 아니다.

### 8.2 사용자 확인을 반영한 최종 해석

설치일보다 이른 검사이력은 **정상적인 과거 조회 자료**이다. 설치일이나 검사일을 임의 정정하지 않고, 데이터 오류로 분류하지 않는다.

- 해당 이력을 보유한 Tube: 429개
- 설치 이전 검사결과: 584건
- 원본 검사이력 435건·결과 6,084건 유지
- Tube 이력 화면에 `설치 이전 이력 · 조회 전용` 표시
- 대시보드의 오류 검토 목록에서 날짜 선후관계 항목 제거
- 현재 감육 순위·잔여수명·현재 감육 추세 표시·재검사 비교에는 현재 설치분 자료만 사용
- 장비 설치일과 Tube 설치일 중 늦은 날짜를 현재 설치분의 경계로 사용
- 같은 날짜는 현재 설치분에 포함하되, 경과시간이 없는 부식속도는 계산하지 않음
- 기존 재계산 경로에도 설치 이전 결과를 제외하는 조건 추가

현재 설치분에 해당하는 결과 ID 조회에서는 5,500건이 확인되었다. 이 수는 계산 입력 후보의 날짜 기준 수량이며 모든 결과가 수명 산정에 충분하다는 뜻은 아니다.

주요 구현: `domain/inspection_lifecycle.py`, `services.py`, `iris_v2_history.py`.

## 9. 정밀 분석 Tube Sheet Map 개선

### 9.1 표시·크기

- 밝은 회청색 배경과 읽기 쉬운 글자색 적용
- 기본 Map 높이 PC 580px, 모바일 520px
- 밀집된 배열은 내부 가로·세로 스크롤 제공
- 행·열 번호와 격자선 표시
- X축 위·아래에 열 번호, Y축 왼쪽에 행 번호, 오른쪽에 행별 표시 Tube 수
- Tube 툴팁에 Tube 번호·행·열·상태·감육률 표시
- 행·열 값이 없으면 임의 번호를 만들지 않음
- 격자선은 행·열별 표시 위치 중심 기준이므로 추정 배치에서는 위치 안내용으로 사용

### 9.2 격자·축 번호 토글

- `Tube Sheet Map` 제목 바로 뒤의 작은 토글 하나로 격자·행열 번호를 함께 켜고 끔
- 최초 기본값은 켜짐
- 상태를 브라우저 `localStorage`의 `iris2.precision-map.overlays`에 저장
- 새로고침·다른 설비 선택·같은 브라우저 재실행 후에도 유지
- 저장소 차단 시 현재 화면 토글 동작은 유지하되 영구 저장은 보장하지 않음
- 다른 PC·브라우저·다른 접속 주소에는 별도 저장됨

### 9.3 패널 크기 조절

- Map과 부식측정결과 표 사이의 세로 조절선을 드래그해 너비 비율 변경
- Map 아래 조절선을 드래그해 세로 높이 변경
- 조절선을 선택한 뒤 방향키로도 변경 가능
- 가로 비율은 25~75%, Map 높이는 240~1,600px 범위
- 좁은 화면에서는 상하 배치를 유지하며 가로 조절선 숨김
- 패널 크기 자체의 새로고침 후 영구 저장은 구현하지 않음

### 9.4 배치 오류 수정

이전 템플릿의 2개 패널과 조절선을 포함한 새 3열 CSS가 함께 로드되면서 결과표가 조절선 너비로 축소되는 문제를 실제 브라우저에서 확인했다.

- Map·조절선·결과표의 열 위치를 명시해 수정
- 공통 테마가 검은 Map 배경을 덮어쓰던 충돌 수정
- 전역 버튼 스타일 때문에 Tube가 타원처럼 보이던 크기·패딩 수정
- 결과표의 글자·여백·내부 스크롤 정리
- 관련 정적 파일 URL에 버전값을 부여해 캐시 혼용 완화

## 10. Wall Loss 색상 설정과 Map·범례 통일

처음 적용했던 이미지 기반 10% 간격 고정 팔레트는 최종 기준이 아니다. 현재는 저장된 공통 Wall Loss 설정을 사용한다.

| 키 | 기본색 | 의미 |
|---|---|---|
| NORMAL | `#14b8a6` | 정상 시작색 |
| WARNING | `#f59e0b` | 해당 설비의 주의 임계값 색상 |
| CRITICAL | `#ef4444` | 해당 설비의 위험 임계값 색상 |
| NOT_INSPECTED | `#64748b` | 미검사·감육률 미등록 |
| PLUGGED | `#334155` | 사용중지·Plugged |

- 정밀 분석 Map, 기존 Tube Map과 범례가 같은 저장 색상을 사용한다.
- 정상→주의→위험 임계값 사이의 감육률은 색상을 연속 보간한다.
- 범례의 상태별 수량과 색상, 연속 색상 막대를 함께 표시한다.
- Plugged 상태는 감육률 색상보다 우선한다.
- 범례의 수량은 실제 표시 위치 집계이므로 미연결 Layout 위치도 미검사로 표시될 수 있다.
- 색상 저장·초기화 후 같은 브라우저의 열린 Map 탭은 저장 이벤트로 자동 새로고침한다.
- 다른 PC는 새로고침해야 저장 색상이 반영된다.
- 저장소 사용이 막힌 브라우저에서는 자동 탭 갱신이 제한될 수 있다.

주요 파일: `static/wall-loss-color-sync.js`, `templates/wall_loss_colors.html`, `static/precision-analysis.js`, `static/tube-map.js`.

## 12. Map과 표의 양방향 선택 연결

| 사용자 동작 | 연결 동작 |
|---|---|
| Map Tube 선택 | 해당 표 행을 선택하고 내부 스크롤 후 3회 강조 애니메이션 |
| 표 행 선택 | 해당 Map Tube 위치로 내부 스크롤하고 선택·강조 |
| 같은 Tube의 Map 위치가 여러 개 | 해당 위치 모두 선택 표시 |
| 표에 없는 Tube 선택 | 목록 대상이 아닌 Tube라는 안내 표시 |
| Map 위치가 없는 표 행 선택 | Map 미연결 안내와 하단 Tube 분석 표시 |

선택 강조는 깜빡임 후에도 유지한다. 키보드 Enter·Space로도 표 행을 선택할 수 있다. 움직임 줄이기 설정에서는 깜빡임을 생략한다. 최초 자동 선택은 불필요한 스크롤을 일으키지 않는다.

## 13. 잔여수명 분석의 의미와 예상일 표시

### 13.1 표시 항목

- 허용 Plugging 한도: 총 Tube 수에 한도율을 적용해 소수점을 버린 허용 개수
- 기준일 누적 대상: 실제 Plugged와 계산상 기준일까지 Plugging 판정에 도달한 Tube의 합계
- 선택 Tube 예상: 처리 완료 / 판정 기준 도달 / 예상 연도 / 산정 불가
- 열교환기 예상 잔여수명: 허용 개수를 처음 초과하는 연도까지의 잔여 연수
- 한도 초과 예상일: 허용 개수를 처음 초과하는 실제 예측 날짜
- 계산 기준일: 해당 계산의 기준 날짜

예를 들어 허용 한도가 20%, 18개라면 18개까지 허용이며 **19번째 대상의 예상일**을 한도 초과 예상일로 표시한다. 기준일 누적 대상 10개는 실제 작업 완료 10개와 같지 않다.

### 13.2 날짜 계산

Tube별 예상일을 날짜순으로 정렬하고 허용 개수를 초과하는 순번의 날짜를 `YYYY-MM-DD`로 표시한다. 부식속도 슬라이더 배율을 바꾸면 날짜와 누적 대상도 다시 계산한다.

- 연수는 기존 연도 차이 방식과 일치하도록 표시한다.
- 이미 초과한 경우 과거 예상일과 0년이 함께 표시될 수 있다.
- 대상 수량이 충분하지 않으면 `한도 미도달`로 표시한다.
- `한도 미도달`은 무한 수명·계속 운전 가능 승인·전 Tube 검증 완료를 의미하지 않는다.
- 실제 막음 작업 기록과 계산상 판정 도달은 구분한다.

## 14. 3D Tube Map 연결

- 정밀 분석의 Map 제목 옆에 `3D 보기 ↗` 버튼 추가
- 기존 인증·권한 경로의 2D/3D Tube Map을 새 탭으로 연결
- 선택한 열교환기, 검사 캠페인, Tube ID 전달
- 도착 화면은 3D 모드로 시작하며 해당 데이터 안에서 Tube를 찾아 선택
- Tube를 찾지 못하면 기존 초기 선택 로직으로 대체
- 기존 3D 화면의 회전·Tube 상세 보기 등 기능 사용

이는 정밀 분석 Map 영역 안에 새 WebGL 렌더러를 삽입한 것이 아니라 **기존 3D 화면으로 이어지는 연결**이다. 최신 작업은 링크 렌더링·선택 전달 코드·문법을 검증했으며, 모든 PC의 GPU/WebGL 환경을 실제 시험한 것은 아니다.

## 18. 기록 해석 시 주의할 점

- 과거 점검 JSON은 해당 시점의 결과를 보존한 것이므로 최신 값으로 자동 갱신되지 않는다.
- 902대·69,141개는 시험용 2대 삭제 전 값이다. 현재 기준값은 900대·69,105개이다.
- 2.9%·3.3%를 설치일 입력 완성도로 해석하던 이전 표시와 현재 92.6%는 집계 목적·분모가 다르다.
- 3.3%는 현재도 사양 수량 대비 개별 Tube 등록률로 유효하며, 설치일 입력률은 100%이다.
- 설치일 이전 검사이력을 오류로 표현한 이전 점검 내용은 사용자 확인에 따라 대체되었다. 최종 기준은 정상 과거 조회 자료이다.
- 소스 반영·단위시험·테스트 클라이언트 검증과 실제 배포 프로세스의 재시작·현장 확인을 구분한다.
- 접속 설정 파일·암호·API 키 등 비밀정보는 본 문서에 포함하지 않았다.

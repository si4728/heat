# 튜브별 검사 횟수 조회

Text-to-SQL에서 `검사를 제일 많이한 튜브 10개 리스트 해줘, 튜브번호 별 1행씩`을 지원한다.

- 기존 검사 횟수 조회 경로에서 서버가 고정 SQL을 생성한다. 모델 생성 SQL의 허용 범위를 확장하지 않는다.
- 선택한 VCM1·VCM2 설비 범위를 유지하며, 미선택 시 허용된 전체 설비를 대상으로 한다.
- 튜브 질문의 기간 기본값은 전체 이력이다. 최근 N년·올해·작년도 지원한다. 기존 설비 순위의 최근 5년 기본값은 유지한다.
- 설비·번들·튜브번호별 한 행으로 묶고, 유효한 튜브 결과를 검사 ID별 한 번 집계한다. 대체된 보고서와 미래 날짜는 제외한다. 검사일이 없으면 보고일을 사용한다.
- 공정, 설비 태그, 번들, 튜브번호, 검사 횟수, 최근 검사일을 반환한다. 모델번호 필드가 아닌 실제 등록된 설비 태그를 표시한다.
- 동률은 공정·설비 태그·설비 ID·번들·튜브번호순이다. 생성 시 서명한 SQL 및 범위를 실행 시 재검증한다.

기존 PC 계정에는 로컬 가상환경으로 `tools/grant_text_to_sql_tube_history.py --apply`를 실행해 튜브·번들 두 테이블의 SELECT 권한만 추가한다. 새 계정 생성 도구에도 해당 권한을 반영했다. Git 갱신만으로 다른 PC의 DB 권한이나 서버 재시작은 처리되지 않는다.

검증: 관련 Python 테스트 94건 통과. 전용 읽기 계정으로 MariaDB 실제 집계를 실행해 상위 10개 및 최상위 US-EV-E-581A / 11-4 / 9회를 확인했다. Node 실행 파일이 없어 JS 문법 검사는 실행하지 못했다.
